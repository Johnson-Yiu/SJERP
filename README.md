# 森爵外贸 CRM + ERP

面向小型外贸团队的轻量业务管理系统。首版覆盖客户、联系人、跟进、产品与 SKU、报价、订单、财务流水、CSV 导入和经营仪表盘。

## 开发与架构原则

1. 当前系统优先满足已经明确、真实存在的业务需求，不为尚未确定的未来需求提前开发功能。
2. 不因为“以后可能会用”而提前增加空 API、未使用字段、Future/Reserved 类字段、半成品模型、未接入前端的预留功能或暂时不会运行的业务流程。
3. “可扩展”主要通过合理的数据边界实现，而不是通过提前堆预留代码实现。
4. 对当前已经确定的业务概念，应尽量保持语义清晰并彼此区分。例如收付款、退款、费用、合同金额调整，不应为了简单而全部混成一种记录。
5. 历史业务记录应尽量保留原始事实，不通过覆盖历史数据实现新的业务状态。
6. 新功能优先通过“新增模块 / 新增关联关系 / 新增服务”扩展现有系统，尽量避免以后必须大规模修改订单、SKU、采购、库存、财务等核心历史数据。
7. 不要求做到“未来绝不需要数据库迁移”。正常的小型 schema migration 是允许的；目标是避免因为当前结构设计错误，导致以后必须进行复杂的数据重构或大规模历史数据转换。
8. 如果未来业务规则尚未确定，宁可暂时不实现，也不要猜测业务规则提前写入系统。
9. 所有预留、兼容或历史逻辑必须有明确实际用途。不保留无调用代码、无实际用途的兼容层或仅为了假想未来存在的接口。
10. 代码审查时必须区分当前正式业务逻辑、历史兼容逻辑与尚未实现的未来需求；尚未实现的需求不得表现得像当前正式功能，避免开发人员或 AI 审查时产生误判。

项目原则摘要：“只实现确定的需求，不提前实现假想功能；通过清晰的数据边界和历史可追溯性保持未来可扩展。”

## 关联详情

- 所有业务列表均支持点击整行打开详情抽屉。
- 客户可查看联系人、订单、采购明细、报价、跟进和财务流水。
- 产品可查看 SKU、销售订单、库存流水、结构化参数和证书档案。
- 联系人、SKU、报价、订单、跟进、流水等记录可继续点击关联数据递进查看。
- 产品参数、产品证书、库存流水提供独立的新建、编辑和删除管理页面。

## 技术栈

- 前端：Vue 3 + Vite
- 后端：Django + Django REST Framework
- 数据库：默认 SQLite，可通过环境变量切换 PostgreSQL

## 本地启动

Windows 可在项目根目录双击“一键启动”脚本：

`启动主工作树.bat`

脚本会在首次运行时自动创建 Python 虚拟环境、安装前后端依赖、执行数据库迁移并初始化空数据库；后续运行会复用已有环境，不会重复灌入演示数据。

启动器内部调用的 PowerShell 文件使用 ASCII 文件名，以避免 Windows 命令行编码导致的路径乱码。

也可以分步启动：

```powershell
# 后端
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r backend/requirements.txt
python backend/manage.py migrate
python backend/manage.py seed_demo
python backend/manage.py runserver

# 新终端启动前端
cd frontend
npm install
npm run dev
```

访问 `http://localhost:5191`。后端 API 位于 `http://localhost:8100/api/`。

`seed_demo` 仅用于本地开发环境的演示数据初始化，不是 QA/UAT 测试夹具，也不能替代真实业务流程验收。它只接受默认本地 SQLite，或由当前隔离运行器提供完整隔离身份的 SQLite；生产/暂存环境、非 SQLite 数据库和未标记的显式 `DATABASE_URL` 会被拒绝。历史 `run_business_flow_checks` 与 `run_edge_business_flow_checks` 管理命令已退役，源码和历史证据保留但不再执行。

## 报价与 PI 工作流

- 在“SKU 管理”的新建或编辑弹窗中上传产品图片；支持 GIF、JPEG、PNG 和 WebP。图片随 SKU 保存，重新打开 SKU 仍可预览，也可在编辑时清除。
- 已保存报价是不可变快照。调整价格、明细或条款时请使用“创建修订版”，并填写本次修改说明；原报价保留不变。新版本仍按 `<根报价号>-1`、`<根报价号>-2` 顺序编号，但会记录实际从哪个版本修改而来。
- 编辑器中的“预览 PI”只预览当前草稿，不会保存。保存并导出后，Excel 文件名严格使用完整报价号，例如 `SJ20260815DE001-2.xlsx`；工作表中的 `Invoice No.` 与文件名中的报价号完全一致。

PI Excel 由后端读取已保存的报价快照，组装 Export DTO 后直接使用 Python `openpyxl` 生成 XLSX。部署环境只需按 `backend/requirements.txt` 安装后端 Python 依赖，不需要 Node.js 或额外的报价导出运行时。

报价模板位于 `templates/quotation/`。字体、颜色、Logo、边框、列宽、静态文案、打印设置等请直接编辑对应模板；代码会保留其样式并只填入数据、复制动态商品行、插入图片和移动下方区域。模板中动态区域的位置集中在 `backend/crm/quotation_template_config.py`，仅在更改数据槽位或行结构时才需同步修改该映射。

## 报价工作台日常流程

1. 在“报价管理”点击任一报价，打开报价专用工作台；概览页可直接预览 PI、导出 Excel、创建迭代版或转为订单。
2. 在“版本谱系”以树状关系查看原始报价及全部迭代版；每个版本保留自己的商品和价格快照、修改说明与直接来源版本。查看其他版本详情后，可用“返回上一版本”回到原版本。
3. 在“重要备注”记录需要跨版本追溯的沟通信息。备注会显示在该原始报价的全部版本中，并标明来源版本；不再生效的备注会保留并以删除线显示，同时记录最近一次失效的时间与操作人，可恢复生效。备注可能已过时，且不一定适用于最终订单，因此不会写入 PI 或 Excel。
4. 点击“转为订单”进入预填订单草稿，补充交期后保存。创建订单草稿不会自动接受来源报价；确认订单时，只有最终使用的 Quote / 最终修订版才会标记为“已接受”。来源报价若已拒绝或过期，则不能确认订单，必须先创建新的报价修订版。同一版本可转出多张订单，订单分页会汇总整个报价链的转单历史。

安装 PostgreSQL 驱动并设置环境变量：

```powershell
pip install psycopg[binary]
$env:DATABASE_URL="postgresql://user:password@localhost:5432/senju"
python backend/manage.py migrate
```

## CSV 导入

系统内“数据导入”页面支持导入客户、产品、SKU 和财务流水。正式订单 CSV 导入暂不开放；订单必须通过报价、订单确认、库存预留和收款计划等正式业务流程创建，避免绕过业务校验。导入产品前请先建立对应分类，财务流水采用新增模式，不会覆盖已有记录。
