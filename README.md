# 森爵外贸 CRM + ERP

面向 5 人以内的外贸团队，覆盖客户、报价、订单、采购、库存、收付款与经营报表。首发只补通现有业务闭环，先在局域网内测，计划约 1–2 个月后迁移阿里云。

**从[首发操作指南](docs/deployment/SMALL-TEAM-LAUNCH-GUIDE.md)开始。** 指南按角色说明访问、导入及日常操作，包含页面入口、核查方法和当前边界。

## 选择运行环境

| 用途 | 入口与数据边界 |
| --- | --- |
| Windows 开发演示 | 在开发工作树根目录双击 `启动主工作树.bat`，由 `start-main-worktree.ps1` 启动。前端默认访问 `http://localhost:5191`，后端端口为 `8100`。脚本会迁移工作树 SQLite，并可能在新库执行 `seed_demo`。只使用演示数据。 |
| 隔离验收 | 由验收负责人提供独立数据库、媒体目录和访问入口，使用合成资料。参考 [O1 环境验收记录](docs/uat-evidence/local-runtime-delivery-01/README.md)和 [D1 隔离试导记录](docs/uat-evidence/history-import-delivery-01/README.md)。 |
| 真实业务运行 | 管理员按 [O1 本地运行交接](docs/deployment/LOCAL-RUNTIME.md)配置并验收 Linux、Gunicorn、Nginx、PostgreSQL 17 和私有媒体卷。真实主机、HTTPS 地址、证书和备份目标待配置并核验。正式入口由管理员交付。 |

业务用户使用管理员提供的 HTTPS 地址和账号登录。登录页或工作台打不开时，记录时间、页面地址和报错交管理员核查。迁移、演示初始化、备份恢复及环境配置由管理员处理。

## 开发与架构原则

1. 当前系统优先满足已经明确、真实存在的业务需求，不为尚未确定的未来需求提前开发功能。
2. 不因为“以后可能会用”而提前增加空 API、未使用字段、Future/Reserved 类字段、半成品模型、未接入前端的预留功能或暂时不会运行的业务流程。
3. “可扩展”主要通过合理的数据边界实现，而不是通过提前堆预留代码实现。
4. 对当前已经确定的业务概念，应尽量保持语义清晰并彼此区分。例如收付款、退款、费用、合同金额调整，不应为了简单而全部混成一种记录。
5. 历史业务记录应尽量保留原始事实，不通过覆盖历史数据实现新的业务状态。
6. 新功能优先通过“新增模块 / 新增关联关系 / 新增服务”扩展现有系统，尽量避免以后必须大规模修改订单、SKU、采购、库存、财务等核心历史数据。
7. 不要求做到“未来绝不需要数据库迁移”。正常的小型 schema migration 是允许的；目标是避免因为当前结构设计错误，导致以后必须进行复杂的数据重构或大规模历史数据转换。
8. 如果未来业务规则尚未确定，宁可暂时不实现，也不要猜测业务规则提前写入系统。
9. 所有预留、兼容或历史逻辑必须有明确实际用途。不保留无调用代码、无实际用途的兼容层或仅为了假想未来存在的接口。
10. 代码审查时必须区分当前正式业务逻辑、历史兼容逻辑与尚未实现的未来需求；尚未实现的需求不得表现得像当前正式功能，避免开发人员或 AI 审查时产生误判。

项目原则摘要：“只实现确定的需求，不提前实现假想功能；通过清晰的数据边界和历史可追溯性保持未来可扩展。”

## 技术栈

- 前端使用 Vue 3 和 Vite。
- 后端使用 Django 和 Django REST Framework。
- 开发演示使用 SQLite，业务运行方案使用 PostgreSQL 17。
