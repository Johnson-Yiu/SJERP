# ISS-051｜开发与生产环境安全分离

本说明是部署前配置清单，不代表已经连接或部署真实生产环境。代码在导入 `APP_STAGE=production` 时主动拒绝不安全默认值；真实服务器、反向代理、数据库和密钥仍需在目标环境单独验收。

## 开发环境

开发环境默认保持现有 Codex 工作方式：`APP_STAGE=development`、`DJANGO_DEBUG=true`、本地 SQLite、开发超级管理员入口和关闭的正式 RBAC。该身份由服务端 `development_superadmin_enabled()` 统一判定，不依赖前端角色名称，也不会因为生产配置而修改现有开发账号或数据。

开发密钥只用于本机，不能用于任何共享、测试或生产环境。仓库内的 `backend/environment.example` 只包含占位值。

## 生产环境注入

生产必须从外部配置/密钥管理器注入以下变量，不把真实值写入 GitHub、日志或测试证据：

```text
APP_STAGE=production
DJANGO_DEBUG=false
DJANGO_SECRET_KEY=<独立随机密钥，至少32字符>
DATABASE_URL=postgresql://<独立生产账号>:<外部注入密码>@<独立数据库主机>:5432/<独立生产库>
DJANGO_ALLOWED_HOSTS=<正式ERP域名>
CORS_ALLOWED_ORIGINS=https://<正式ERP域名>
CSRF_TRUSTED_ORIGINS=https://<正式ERP域名>
DEVELOPMENT_SUPERADMIN=false
RBAC_ENFORCEMENT=true
SECURE_SSL_REDIRECT=true
SESSION_COOKIE_SECURE=true
CSRF_COOKIE_SECURE=true
MEDIA_ROOT=<独立私有媒体目录>
```

配置模块还会拒绝通配符 `ALLOWED_HOSTS`、HTTP 的 CORS/CSRF 来源、生产 SQLite、空/过短/开发默认密钥、开启 DEBUG、开发超级管理员或关闭 RBAC。生产默认启用 HSTS、`HttpOnly`/`SameSite=Lax` 会话保护、`X-Content-Type-Options` 和 `X-Frame-Options`。

HTTPS 终止必须在受控反向代理完成；代理需要清理客户端伪造的 `X-Forwarded-Proto` 后再设置可信的 `https` 值，并把 `/media/` 保持为私有路径，只通过应用授权入口访问。生产配置没有在本轮连接真实服务器或真实数据库，目标环境验证标记为 `DEPLOYMENT_VERIFICATION_PENDING`。

## 独立实名账号与权限边界

生产创始合伙人应使用各自的 Django 用户名、姓名和密码，通过标准 `createsuperuser`/受控账号流程建立，再按应用角色和数据范围配置 `EmployeeProfile`。不得复制开发环境默认身份、共享账号或把 `DEFAULT_OPERATOR_NAME` 当作正式审计人。代码不创建虚假生产用户，也不把账号资料写入仓库。

应用超级管理员是 ERP 业务权限概念；数据库账号、服务器/操作系统账号、反向代理账号和密钥管理器账号必须由运维分别管理。应用权限不会自动授予这些基础设施权限。

生产 ERP API 使用 Django SessionAuthentication；未登录业务 API 返回 401，已登录但无模块权限返回 403。`/api/session/current-operator/` 只返回当前登录/未登录状态和权限摘要，不返回业务数据；前端路由守卫在权限状态读取失败或模块无权时进入受限页。ISS-017 附件仍通过受保护的 API 入口，环境变量不能绕过记录级授权。

## 交接前检查

1. 在隔离环境先执行 `python backend/manage.py check`、迁移检查和后端测试。
2. 用不含真实密钥的临时配置验证生产导入会拒绝不安全值；日志只记录变量名和布尔结果，不打印值。
3. 在独立 PostgreSQL 和私有媒体目录完成迁移、备份/恢复、未登录 401、无权 403、反向代理 HTTPS、Cookie 和附件直链实测。
4. 由运维确认 secret rotation、数据库最小权限、服务器账号隔离和日志脱敏后，才可移除 `DEPLOYMENT_VERIFICATION_PENDING`。
