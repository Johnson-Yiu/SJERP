## 测试结论

- **PASS（限本次场景）**：客户、报价、订单、采购、部分到货、共享库存、跨订单成本分配、分批发货、收付款、退款作废和报表形成可追溯的 UI 业务链。已确认取消单未进入有效销售金额；作废退款不再影响现金汇总；已出库库存不足时，收货冲销被拒绝且库存历史保留。
- **FAIL / P1**：真实 UI 允许一张全部发货但仍欠 USD 160 的订单直接“完成订单”。完成后工作台显示“当前没有待处理事项”，应收页仍有 USD 160 待结；完成状态与应收催收提示脱节。需业务决定“完成”代表履约完成还是履约和收款均完成，再按决定修复入口校验或保留应收待办。
- **BLOCKED / P1 内测准备**：本次只能以开发超级管理员运行，未能验证 self、部门或无模块权限用户的真实 UI/API 边界。项目约定要求内测前完成全站权限验收；本次没有改变 RBAC 设置，因此不应据此开放受限角色内测。
- **BLOCKED**：合同变更批准、附件上传/预览/下载、受限文件 URL 拒绝、独立采购（无销售订单）、安全条件下的收货冲销和 CSV 下载文件内容未在本轮真实 UI 中验证。报表页面可见的数字已核对，CSV 按钮曾点击，但没有取得并检查下载文件。
- 未发现本轮已成功路径中的其他确认失败；这不代表未覆盖入口已通过。

## 本轮真实 UI 记录

所有记录均来自内置浏览器操作与页面/API 返回；对象 ID 属一次性隔离数据库，结束后会随测试库清理。

1. 建立两名客户、两个 SKU、两家供应商及 SKU 供应来源。客户甲的报价 `SJ20261013CN001`（SKU-000001，3 件，USD 360）转为 `SO-2026-00001`，确认后取消。工作台显示已取消、应收计划取消，历史合同金额 USD 360 保留；销售报表排除该单。
2. 客户乙报价 `SJ20261013CN002`（SKU-000002，2 件，USD 320）转为 `SO-2026-00002`。采购 `PO-2026-00001` 两次各入库 1 件；采购计划按 USD 24 / 56 登记预付与尾款；商品 USD 80、公共运费 USD 10 分摊到订单，订单成本显示商品 ¥576、附加费用 ¥72。销售分两批各发 1 件，应收按 USD 96 / 224 收齐，订单完成。
3. 对 SO-00002 通过 UI 登记 USD 10 客户退款，随后按原因作废。订单收款余额恢复，退款不留在最终现金净额内。
4. 建立 `SO-2026-00003`（客户甲）与 `SO-2026-00004`（客户乙），各需 SKU-000002 1 件。共享采购 `PO-2026-00002` 采购 2 件，分两次到货；商品 USD 80 + 公共运费 USD 10 按数量拆分至两单，每单商品 USD 40、运费 USD 5；供应商计划 USD 24/56 均完成付款。两单分别发货，回查 PO2 与两个订单的关联。
5. SO-00003 发货后尝试冲销其已被销售出库消耗的采购到货。页面返回“当前 SKU 实际库存不足以冲销，请先处理后续出库”，采购到货历史保留，库存未被倒扣。
6. SO-00004 全部发货但尚未收款时，UI 仍提供“完成订单”。点击后状态变“已完成”，待办卡片变为“当前没有待处理事项”，但应收仍为 USD 160。完成状态后，应收计划仍可正常登记 USD 112 与 USD 48，待结余额归零。状态提醒落差为本轮确认 P1。
7. 最终报表（2026-01-01 至 2026-10-13）：有效销售订单 3 张、4 件、¥4,608；已确认净现金 ¥2,304、8 笔。计算：收款 320+160=USD 480，供应商付款 80+80=USD 160，退款已作废；按 UI 汇率 7.2 折人民币，净额 (480−160)×7.2=¥2,304。
