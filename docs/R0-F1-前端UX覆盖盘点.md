- **已专项优化并接受/冻结**：有专项 UI/UX 记录，且用户明确接受冻结；仅冻结该页面与该记录所列范围。

- **本轮已优化，待独立复审**：R0-F1 财务页面本轮范围；不扩展为业务逻辑或其他模块验收。

## 本轮财务页面变更

- 财务流水、收款计划、付款计划和财务概览取消页面自身重复外边距，与全局内容容器对齐；顶栏保留唯一页面标题。
- 流水和计划列表用具名表单提交条件，条件写入路由查询参数，刷新/返回时恢复；开始日期晚于结束日期时显示中文提示并阻止查询。
- 流水表单按流水信息、业务关联、付款信息分组，弹窗可滚动并支持明确关闭；核销与作废弹窗展示可操作对象和现有余额，成功/失败状态可见。
- 概览分为“所选期间”和“当前余额”；说明销售按订单日期、现金流按实际发生日期，待收待付和预收预付为当前余额，预计订单利润是经营估算。没有改变后端统计或财务规则。

| 基线行为（`bf79ef8` 源码） | 本轮结果 | 可见影响 |
|---|---|---|
| 流水状态/方向由控件变更触发查询，搜索和日期输入走不同触发方式；筛选没有完整保存在 URL。 | 用统一查询/重置表单提交；搜索、状态、方向、日期范围写入 URL，刷新与返回能还原。 | 用户可先填完整条件再查询，避免输入过程触发结果跳动；返回时保留筛选上下文。 |
| 应收/应付搜索使用延迟请求，状态、逾期和到期日条件分散控制；查询状态难以从地址栏恢复。 | 统一显式提交，区分默认未结清与全部状态，并同步 URL；校验日期范围。 | 查询过程一致，清除条件后能明确看到全部或默认未结清结果。 |
| 财务概览把期间经营/现金数据与待收、待付等余额指标放在同一组卡片中。 | 分成“所选期间”和“当前余额”，增加统计日期口径说明、导出/刷新状态和财务入口。 | 用户能区分期间累计与当前余额，并理解预计利润为经营估算。 |
| 新建、核销和作废对话框字段层级较平，成功后反馈不统一。 | 分组字段、可滚动弹窗、明确取消/确认和成功/失败提示。 | 操作对象与余额更清楚；完成后能确认结果并回到可刷新的列表状态。 |

以上“基线”来自 Git 基线源码和自动回归差异，不存在可归档的基线浏览器截图；本轮只对当前页面进行了真实截图目视检查。因此本记录不将它描述成已完成的像素级前后截图对比。
