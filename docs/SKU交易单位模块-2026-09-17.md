# SKU 交易单位模块

完成验收：2026-09-21。

## 设计与边界

同一 SKU 保留唯一库存基础单位，例如 m。10 m/卷、20 m/卷、100 m/卷分别是该 SKU 的交易规格，不派生新的 SKU，不进入产品参数组合、销售型号或供应商 SKU 身份。

现有 `SKUPackagingProfile` / `PackagingTemplate` 继续负责装箱容量、尺寸、重量。新增 `SKUTradeUnit` 只负责交易计量，两者独立：外箱容量、单重及实际装箱数量仍使用基础单位。

库存可用量与预留按基础数量计算。库存流水记录入库、出库当时的交易数量和包装规格，供人工追溯；系统不维护“未拆封卷数”或每卷剩余长度，基础库存充足不代表某种卷长的完整卷库存充足，仓库需核实实际包装。不同包装可以登记等量基础数量，具体拆卷/重新包装作业不是本模块的自动能力。

## 数据结构

`SKUTradeUnit`：

| 字段 | 用途 |
| --- | --- |
| sku | 所属 SKU，保护引用 |
| supplier | 可选供应商约束；为空表示通用规格 |
| name / unit | 规格名称及交易单位，如 10m Roll / Roll |
| factor | 1 个交易单位对应多少基础单位，大于零，2 位小数 |
| allow_fraction | 是否允许非整包装交易；默认仅整包装 |
| active / is_default | 启停和 SKU 默认规格；数据库确保最多一个默认且默认必须启用 |
| notes | 管理备注 |

报价行、订单行、采购行、库存流水、收货行、发货行增加：

| 字段 | 用途 |
| --- | --- |
| trade_unit | 规格引用，PROTECT，不允许删除历史依据 |
| trade_quantity | 交易数量，2 位小数 |
| trade_unit_price | 交易单价，4 位小数；实物发货行可以为空 |
| trade_snapshot | 规格名、单位、基础单位、系数、非整包装规则的不可变快照 |

兼容性约定：原有 `quantity` **继续代表基础数量**，原有 `unit_price` / `unit_cost` **继续代表基础单位单价/成本**。基础单价精度提升至 12 位，历史接口保持原有四位小数输出；非整除的换算价格按实际精度输出。

合同金额使用交易数量 × 交易单价，避免使用除法得到的基础单价反算金额。旧单据没有交易字段时使用原计算方式。采购成本分配、应收应付、经营报表、客户/SKU 汇总使用同一金额口径。

数量换算使用 Decimal。当前库存系统支持 2 位小数，因此换算结果超过 2 位小数、非有限数、负数或溢出会被拒绝，而不会静默四舍五入。

## 服务端数据流

1. `crm/trade_units.py` 根据 SKU 和规格 ID 查询可信主档，重新计算基础数量；客户端传入的系数和快照不能覆盖服务端结果。
2. 新交易只能选择启用规格；同一来源报价/订单的修订、转单以及履约可以继续使用已停用的历史规格。
3. 规格定义一经保存不可编辑。修改卷长需停用旧记录、创建新规格。名称、所属 SKU、供应商、单位、换算系数和整包规则均受保护。
4. SKU 存在交易规格或历史业务后，禁止直接更改基础单位。不能把已有米数账本改名为卷数账本。
5. 报价数量规则/MOQ 检查、库存预留、采购缺口、在途量、收货余量、发货余量、预计装箱、实际装箱、成本分配数量仍按基础数量执行。
6. 收货/发货规格可以与采购/销售规格不同，只要属于相同 SKU 并满足供应商约束。超到、超发及可用库存校验在换算后执行，事务保证失败不会留下半条业务。
7. 超发拆分为正常和追加行时，流水按分摊数量保存可精确表达的交易数量；无法以当前两位交易精度表达的部分记录为基础单位，避免制造错误的小数包装。
8. 原开发超级管理员权限入口保持不变；未启用 RBAC，未改变开发人员访问权限。

## 接口

- `GET /api/sku-trade-units/`：列表，支持 `sku`、`supplier`、`active=1` 和搜索。
- `POST /api/sku-trade-units/`：创建规格。
- `PATCH /api/sku-trade-units/{id}/`：启停、默认、备注；定义字段不能改写。
- `GET /api/skus/` / SKU 详情：增加 `trade_units` 集合。
- 原报价、订单、采购、库存、收货和发货接口保留，增加交易字段。

按卷创建合同明细示例：

```json
{
  "sku": 17,
  "trade_unit": 5,
  "trade_quantity": "100",
  "trade_unit_price": "8.0000"
}
```

假设规格 5 为 10 m/Roll，服务端保存基础数量 1000 m，基础单价 0.8，交易金额 800。不需要客户端再传 `quantity`；即使传入，也以服务端换算为准。

收货填写 `trade_unit_price` 表示每包装实际成本。发货只需交易规格和数量，不需要单价。不选规格时，继续提交原 `quantity` 和 `unit_price` / `unit_cost`。

## 前端入口

- 左侧菜单「交易单位」和 SKU 编辑页的「管理此 SKU 的交易单位」。
- 管理页面提供搜索、SKU 筛选、供应商限定、默认规格、整包装规则、启停。
- 报价编辑器、报价转订单草稿、独立订单创建/编辑、关联快捷创建、采购创建均可选择交易规格并显示基础数量。
- 选择默认规格的新行使用每包装价格；合同编辑时切换规格会换算参考单价，数量保持当前输入。收货/发货切换规格时保留基础总量并换算交易数量；无法整包交付时明确提示。
- 同一 SKU 可用“增加规格行”录入多个包装规格；重新选择 SKU 不会覆盖或合并这些行，删除明细仅删除当前行。
- 验货入库、手工库存流水、发货弹窗提供相同选择器；发货已由文本提示框改为可审核的表单。
- 报价/订单明细显示成交单位、数量、单价，并同时显示基础数量。
- 库存列表标明 SKU 基础单位，顶部按基础单位分别汇总；流水详情显示原始交易包装快照。
- 采购已到/剩余量、履约数量和成本分配基数明确使用基础单位。
- PI 预览和 Excel DTO 输出交易数量/单位/单价，并在描述中附上包装换算与总基础数量。
