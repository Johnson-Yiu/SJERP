# SKU 参数与供应商改造说明

## 使用入口

产品管理 → 打开产品抽屉 → SKU 矩阵 → 表格下方「SKU 参数与供应商」。

- **供应商分配**：添加供应能力规则 → 预览匹配 → 保存；下方按 SKU 查看候选，支持人工加入、排除及恢复规则匹配。
- **参数变更**：创建草稿 → 新增参数 / 降为普通属性 / 补值 / 添加实际拆分组合 → 保存并分析 → 核对结果后发布。
- 新建 SKU 组合页默认不勾选组合，只创建选中的实际组合。整批 SKU 创建使用事务，任何一项校验失败均回滚。
- 单个供货档案的型号、价格、MOQ、交期及供货特点仍在 SKU 编辑页维护。

## 原实现检查结论

| 环节 | 改造前的实际行为与风险 | 本次处理 |
|---|---|---|
| 数据身份 | SKU 使用独立数据库 ID；SKU Code 不可修改，物理删除已禁用 | 保留原框架 |
| 参数增删 | 分类属性配置会影响随后参数解析；已有 SKU 不立即重建，但后续保存可能采用新规则 | 对已有产品冻结 V1；之后通过产品参数方案发布变更 |
| 身份修改 | 勾选确认后，仍可把不同参数的商品保存到原 SKU ID 下；历史快照不能解决库存实物身份改变 | 普通编辑接口拒绝改变身份参数或所属产品；进入补值、拆分、合并流程 |
| 重复组合 | 已有身份签名校验，但旧签名可能与后来的分类标签不同 | 除签名查询外，再按冻结规则比较现有有效 SKU；批量创建事务内重新校验 |
| 普通属性 | 无身份维度时曾回退为全部参数参与身份 | 普通属性不参与身份签名；取消全部维度后归为同一基础组合 |
| 旧标签 | 实库存在“色温”存储键与“色温/发光颜色”分类标签不一致 | 兼容旧键、大小写及分类前缀；不回写实库旧 SKU 参数 |
| 历史记录 | 报价、销售单、采购行、库存流水已有不同范围的商业字段快照 | 保留原快照链路；新增采购行供货特点快照 |
| 供应来源 | 已有 SupplierSKU，但保存服务方法误放在 OperationLogSerializer 下 | 恢复到 SupplierSKUSerializer；禁止供货档案改挂其他 SKU / 供应商 |

## 参数变更如何处理

1. 草稿不会改写 SKU 或业务单据，保存后可以继续编辑、丢弃。
2. 新维度为原商品补充信息且没有形成拆分：原 ID、Code、名称与型号保留，保存旧参数版本。
3. 修改已有身份参数、拆分一个 SKU、移除维度后出现碰撞：建立新 SKU，记录旧 → 新关系，旧 SKU 停用。
4. 普通属性取值在合并时有冲突：新 SKU 留空，旧值保留在来源 SKU；如该属性必填，先解决冲突才能发布。
5. 原库存、预留、在途与订单不自动转移，历史行不修改 SKU 外键。旧订单继续履行；新报价、订单、采购不能新选停用 SKU。归并历史 SKU 不能重新启用。
6. 方案与 SKU 数据发生变化后，旧草稿不能直接发布；前端修改已分析草稿后必须重新分析。发布及版本写入在事务内完成。
7. 分类页现在是新产品初始参数模板。已经冻结参数方案的产品，参数增删请从本产品的「参数变更」入口处理。

## 供应商业务流程

供应能力规则按产品保存参数范围；同一参数内是“任一值满足”，不同参数之间是“同时满足”。留空的参数不限，填写的条件采用忽略大小写的文本精确匹配，建议使用 SKU 中保存的完整值，例如 `12V`。

规则动态生成候选名单，不会为理论组合提前创建 SupplierSKU。共同特点保存在规则上；现有供货档案和历史采购不随规则变化。多个重叠规则的共同特点按规则 ID 顺序覆盖，单 SKU 人工特点优先。

采购单决定本次实际供应商。保存采购时，有供货档案则引用；无档案则按需创建，并复制当时共同特点。同一供应商有多个来源且没有首选时，必须明确选择。人工排除的供应商不能新建采购，恢复候选资格后才可使用。

不同采购单可以为同一标准 SKU 选择不同供应商。采购行保存来源及特点快照；之后修改供货档案不影响原采购记录。

## 使用边界

- 新建的拆分 / 合并 SKU 需要补充销售型号、包装和供货资料；库存归属须核对实物后通过库存业务处理，系统不会猜测数量如何分配。
- 原有历史快照的完整程度保持原状；新增供货特点快照只覆盖改造后的采购，不伪造过去的数据。
- API 和本次业务服务承担校验；直接数据库写入、绕过服务的 ORM 批量修改仍需维护人员自行遵守规则。SQLite 下未做多进程压力测试。
- 开发超级管理员权限保持现有约定，本次不启用 RBAC。
