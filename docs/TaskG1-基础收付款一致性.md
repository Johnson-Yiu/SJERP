# Task G1：基础收付款一致性

本阶段只处理已明确存在的合同资金收付一致性，复用现有 `Transaction`、`PaymentPlan` 与 `AdvanceAllocation`，不新增总账、会计凭证、Credit Note、Debit Note 或合同金额调整模型。

## 业务边界

- 客户退款是已经收到的订单货款实际退回；供应商退款是已经支付的采购款实际退回。
- 退款不是订单费用。售后赔偿、客户运费补贴、质量赔偿等合同金额不变的支出，应登记为订单费用类别。
- 合同金额调整不属于本任务，后续在业务规则明确后独立设计。

## 计划余额与历史

退款按最近结清的有效收付款计划优先回退，减少对应计划的 `settled_amount` 并重新打开余额。跨多个计划时，退款流水使用已有 `split_from` 关系保留拆分历史。

退款不会删除原收付款、预收预付核销或退款流水。退款作废会反向恢复对应计划余额；若恢复会使计划超出合同金额，或作废原预收预付会导致已结金额不足，系统拒绝操作并保留历史记录。
