# Task J1：系统入口与经营视图收敛

## 经营概览

- 销售额、订单数、月度销售、重点客户及品类表现只纳入已确认、生产中、已发货和已完成的正式销售订单；草稿和已取消订单不计入。
- 订单级销售额使用当前有效合同金额（订单商品金额、运费、折扣及已确认合同金额调整）乘订单汇率。
- 品类表现是商品分类销售额，只汇总商品行，不将没有 SKU 分类归属的运费、折扣或合同金额调整分摊到分类。
- 经营概览中的客户和待跟进事项可进入对应记录详情。

## 报表口径

- 销售、采购和利润报表排除草稿与已取消合同；现金报表只统计已确认流水；库存报表按真实库存流水统计期间净变动。
- 经营概览和销售报表的订单级销售金额在相同期间内按同一有效合同金额口径汇总。SKU、产品和品类维度仍按商品行展示，订单金额调整作为独立项目，不强行分摊。
- 销售额不等于收款；现金流不等于利润；预计订单利润是经营估算，不等于会计净利润。

## 跨模块入口

- 经营概览的客户与跟进事项、财务概览的到期应收/应付合同，使用现有 `?detail=<id>` 详情入口。
- 应收跳转通过 `order` ID， 应付跳转通过 `purchase_order` ID，不通过合同编号猜测数据库记录。
- 顶部只显示当前服务端返回的操作人信息；没有实现的搜索和通知入口不作交互控件展示。

## 数据导入安全

- 客户、产品和 SKU 按各自业务编号匹配。主数据创建与更新经过对应序列化器校验；客户导入不修改状态或下次跟进日期，新客户沿用线索默认状态。
- 产品导入要求分类已存在，不自动创建分类；SKU 导入遵守产品归属、身份变更和已有业务记录单位保护规则。
- 财务流水采用正式流水服务新增。重复流水号报错，不覆盖已有历史记录。
- 正式销售订单 CSV 导入暂不开放。订单必须通过业务流程创建，以保留报价、库存预留和收款计划等关联。
- 每一行导入都在独立事务内执行，并继续返回逐行新增、更新和错误结果。
