# ISS-018｜数据库与附件一致性备份恢复运行手册

本文件是部署前的运行手册和隔离演练边界，不代表已连接生产服务器、修改生产权限或部署定时任务。它与 ISS-047 的私有 `MEDIA_ROOT`、ISS-051 的环境隔离和 ISS-043 的审计备份要求一起使用。

## 当前架构审查结论

当前仓库的目标拓扑仍是单服务器：

```text
Nginx（只代理认证 API）
        │
        └── Gunicorn/Django ── PostgreSQL
                    │
                    └── 独立持久化私有 MEDIA_ROOT
```

实际仓库没有生产 PostgreSQL、快照服务、Nginx 实例、systemd 定时器或异地存储可供本轮连接。本轮只在隔离 SQLite 和临时私有媒体目录上执行真实备份/恢复；生产 PostgreSQL、独立故障域、代理规则、加密副本和 RPO/RTO 仍为 `DEPLOYMENT_VERIFICATION_PENDING`。

## 一致性契约

不能把独立的 `pg_dump` 和独立的文件复制结果直接称为同一恢复点。本实现采用以下可核对契约：

1. 备份前必须停止 ERP 写入，或由运维将应用置于明确的维护/静默窗口；命令必须显式传 `--quiesced`，否则立即失败。
2. 在静默窗口内先建立数据库事务快照，再复制 ISS-047 私有媒体清单中的每个文件；复制后重新计算源媒体清单，任何变化都会丢弃整个归档。
3. 数据库快照、媒体目录、恢复配置白名单、SHA256 清单和一致性元数据进入同一个 ZIP 归档。归档完成后再做 ZIP CRC 和归档 SHA256 校验。
4. 恢复必须写入新的隔离目录；先验证归档路径、数据库 SHA256、SQLite `integrity_check`、媒体逐文件 SHA256 和配置 SHA256，全部通过后才写入目标。
5. 清单只保存 `MEDIA_ROOT` 相对路径、大小和 SHA256；不保存绝对服务器路径、密钥、数据库连接串或真实凭证。

当前命令只接受文件型 SQLite。遇到 PostgreSQL 会 fail-closed，避免未经真实快照绑定就宣称生产一致性。生产 PostgreSQL 方案必须在同一维护窗口停止应用写入，以 `pg_dump` 或经 DBA 验证的快照建立数据库副本，并把该副本和私有媒体副本、清单一起打成一个归档；如果使用 PostgreSQL 导出快照和文件系统快照，则必须由目标环境记录同一快照标识。没有该证据时保持 `DEPLOYMENT_VERIFICATION_PENDING`。

## 本地命令

```text
python backend/manage.py create_consistent_backup \
  --database /srv/sunjack/isolated.sqlite3 \
  --media-root /srv/sunjack/private-media \
  --output-dir /srv/sunjack/backups/local \
  --backup-id 20261027T020000Z \
  --quiesced \
  --status-file /srv/sunjack/backups/status/latest.json

python backend/manage.py restore_consistent_backup \
  --archive /srv/sunjack/backups/local/erp-backup-20261027T020000Z.zip \
  --target-dir /srv/sunjack/recovery-drill/20261027 \
  --result-file /srv/sunjack/recovery-drill/20261027-result.json

python backend/manage.py prune_erp_backups \
  --directory /srv/sunjack/backups/local
```

`prune_erp_backups` 默认只生成保留计划；确认副本已复制到独立故障域后，运维才可在目标环境显式增加 `--apply`。策略按归档元数据保留最近 7 个日备、最近 4 个周备和最近 3 个月各一个月备，层级取并集，并同步清理同名 `.age` 副本。

## 每日自动化样例（未部署）

定时器必须先停止应用写入，再执行备份，失败以非零退出码和状态 JSON 交给现有监控/告警；不得把“脚本启动成功”当作备份成功。下面只是交给运维的样例，不包含主机名、账号、密钥或真实 age recipient：

```ini
# /etc/systemd/system/sunjack-backup.service
[Unit]
Description=SUNJACK ERP quiesced database and private media backup
OnFailure=sunjack-backup-alert@%n.service

[Service]
Type=oneshot
WorkingDirectory=/srv/sunjack/current/backend
ExecStartPre=/usr/bin/systemctl stop sunjack-web.service
ExecStart=/srv/sunjack/venv/bin/python manage.py create_consistent_backup --database /srv/sunjack/data/app.sqlite3 --media-root /srv/sunjack/private-media --output-dir /srv/sunjack/backups/local --quiesced --encrypted-output /srv/sunjack/backups/offsite/latest.age --age-recipient <managed-public-recipient> --status-file /srv/sunjack/backups/status/latest.json
ExecStopPost=/usr/bin/systemctl start sunjack-web.service
WorkingDirectory=/srv/sunjack/current/backend
```

```ini
# /etc/systemd/system/sunjack-backup.timer
[Unit]
Description=Daily SUNJACK ERP backup

[Timer]
OnCalendar=*-*-* 02:00:00
Persistent=true

[Install]
WantedBy=timers.target
```

在 PostgreSQL 生产部署中，上述 `--database` 不能直接套用 SQLite 命令。运维必须使用已验证的 PostgreSQL 归档/快照适配器，并把数据库、媒体和清单放入同一一致性归档；当前仓库没有这个可执行生产适配器，也没有运行真实 PostgreSQL。

## 加密副本与故障域

`--encrypted-output` 只接受 age 公钥 recipient，并调用环境中受管控的 `age` 可执行文件；私钥不进入仓库、命令行或状态日志。当前开发机没有已核验的独立异地存储和生产密钥管理，因此不能把本地 ZIP 或模拟 age 调用写成加密异地备份 PASS。目标环境需证明：本地副本与加密副本位于不同故障域、管理员最小可读、复制成功可检测、恢复时可取得私钥且轮换不丢失历史副本。

## 恢复演练核对清单

- [x] 归档中数据库、媒体、配置和清单为一个可校验恢复单元。
- [x] 数据库行、金额、库存数量和附件相对路径在隔离 SQLite 演练中核对。
- [x] 恢复后逐文件 SHA256 与 ISS-047 清单核对。
- [x] 媒体在数据库快照前后发生变化时，整个备份失败且不留下最终归档。
- [x] 归档媒体被篡改时恢复拒绝，并记录耗时与错误。
- [x] 恢复结果写入 `restore-result.json` 或 `--result-file`，备份结果写入 `--status-file`。
- [ ] 真实 PostgreSQL、生产媒体卷、Nginx/反向代理、systemd、独立加密副本、磁盘/inode 告警及 RPO/RTO：`DEPLOYMENT_VERIFICATION_PENDING`。

本轮不连接生产、不生成生产凭证、不上传备份文件、不修改数据库权限、不合并 `master`、不关闭 ISS-018。
