# ISS-047｜单服务器私有文件存储交接说明

本文件是部署前架构和验收记录，不代表已经修改真实服务器、Nginx、数据库或备份任务。目标是为当前单服务器阶段提供可恢复的私有 `MEDIA_ROOT`，同时保留 Django storage 抽象，供 ISS-018 联合备份和未来对象存储迁移使用。

## 结论

当前阶段采用一台应用服务器上的独立持久化私有媒体卷：

```text
Nginx（仅代理 /api/，静态文件只读）
        │
        └── Gunicorn/Django ── PostgreSQL
                    │
                    └── MEDIA_ROOT=/srv/sunjack/private-media
```

`MEDIA_ROOT` 不得位于 release 目录、`STATIC_ROOT` 或官网公开目录。`FollowUpAttachment`、SKU 图片、报价图片快照和产品证书仍使用 Django `FileField`/`ImageField` 的默认 storage，并只能由现有认证 API 按业务权限返回。仓库不添加 `/media/` 静态路由，也不生成游客分享链接。

生产必须显式注入绝对路径 `MEDIA_ROOT`；缺失、相对路径或与 `STATIC_ROOT` 重叠时 Django 启动失败。开发默认使用 `backend/media`，不与生产路径共享。当前默认后端是 `django.core.files.storage.FileSystemStorage`，`MEDIA_STORAGE_BACKEND` 和 `STORAGES["default"]` 是未来迁移对象存储的配置接缝；迁移时必须保留模型文件路径并逐文件校验 SHA256。

## 代理配置样例（未部署）

仓库基线没有实际目标环境 Nginx 配置。下面是交给运维的最小原则样例，不能直接当作生产证书、域名或 upstream 配置：

```nginx
server {
    listen 443 ssl;
    server_name <erp-hostname>;

    # Vue release files only. Do not set root/alias to MEDIA_ROOT.
    root /srv/sunjack/frontend/current/dist;
    location /static/ {
        alias /srv/sunjack/static/current/;
    }

    # A legacy/static media URL must never reach the private volume.
    location = /media { return 404; }
    location ^~ /media/ { return 404; }

    # Protected file responses are under the authenticated Django API.
    location /api/ {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Proto https;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }
}
```

运维验收必须用未登录、无模块权限、越客户范围、已过期缓存链接和已知文件路径分别请求 `/api/media/...`，同时确认不存在任何 `alias`/`root` 指向 `MEDIA_ROOT` 的 location。`/api/media/...` 的 401/403/404 语义必须保留，不能用 Nginx 静态文件返回替代应用授权。

## ISS-018 备份接口准备

`python backend/manage.py private_media_manifest` 是只读媒体清单接口，不是公开 HTTP API，也不执行删除或覆盖。它输出相对路径、大小和 SHA256；`--output` 保存清单，`--verify` 在恢复后的媒体目录上逐文件核对。示例：

```text
python backend/manage.py private_media_manifest \
  --media-root /srv/sunjack/private-media \
  --output /srv/sunjack/backup/media-manifest.json

python backend/manage.py private_media_manifest \
  --media-root /srv/sunjack/private-media \
  --verify /srv/sunjack/backup/media-manifest.json
```

ISS-018 的正式任务仍需由运维在隔离环境把 PostgreSQL dump/备份与同一时间窗口的媒体副本绑定，恢复后先执行 manifest `--verify`，再核对数据库中的附件路径、记录数、金额和图片快照。清单拒绝符号链接，防止备份过程把媒体根目录外的文件纳入。备份副本必须位于独立故障域；本任务不创建远程备份、不上传生产数据，也不改变数据库权限。

## 重启、容量和迁移边界

- 重启验收：停止/启动 Gunicorn 后，用新进程读取同一持久化卷中的已知文件，检查大小和 SHA256 不变。
- 容量验收：运维监控 `MEDIA_ROOT` 所在卷的使用率、inode、最近一次清单生成时间和备份成功时间；阈值和告警通道需在目标环境确定，当前仓库不伪造通过记录。
- 对象存储迁移：先冻结写入或做增量窗口，保留每个模型文件的相对路径/大小/SHA256，切换 Django storage 后重新运行清单和授权 API 回归；禁止把对象存储公开 URL 直接返回给前端。
- 当前不引入多服务器共享卷、集群或异步复制。
