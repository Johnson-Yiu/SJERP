# R0-D4B2-A：财务数据范围

基线：3d5d2907a05b27adcb2ef66c4c7594aa284583b1。仅实施 B2-A，等待独立复审后再决定下一阶段。

## 权限规则矩阵

| 记录 / 入口 | 数据范围 | 模块权限 |
| --- | --- | --- |
| 客户收款、退款、销售订单费用、客户预收款 | 客户归属；同时检查直接客户、订单、计划、分配历史、拆分与重记来源 | transactions 对应操作；改变计划余额另需 finance.update |
| 销售收付款计划 | 订单客户归属 | finance 对应操作；登记流水另需 transactions.create |
| 供应商付款、预付款、采购应付计划 | 共享；不按关联销售订单的销售员隔离 | transactions / finance 对应操作；采购单付款入口另需 purchases.update |
| 销售合同变更 | 订单客户归属 | orders 对应操作；审批生成计划另需 finance.create |
| 采购合同变更 | 共享采购合同 | purchases 对应操作；审批生成计划另需 finance.create，不要求销售模块 |
| 公共费用 | 无客户、无销售订单归属的共享公司费用 | transactions 对应操作 |
| 财务概览、经营概览现金总额、现金报表和 CSV | 复用流水及计划范围；范围外记录不参与总额 | finance / dashboard / reports 查看；现金来源另需 transactions.view；CSV 服务端检查 finance.export / reports.export |
| 财务及采购 Context | 主要记录执行范围校验；相关流水执行同一范围；采购关联销售字段脱敏 | 对应模块查看，关联部分另查模块查看权限 |

保留 development_superadmin_enabled() 和现有 RBAC 开关行为，不修改当前开发人员权限，不增加数据模型或迁移。财务记账服务、退款、冲销、核销算法和历史快照未改动。

## 修复

- 统一流水和计划查询；列表、详情和业务动作复用同一查询，范围外详情返回 404。
- 创建 / 修改时检查客户、订单、计划及重记来源，防止可见记录绑定范围外对象。
- 拆分家族中任一记录涉及范围外业务时，隐藏整组，阻止根流水作废间接修改范围外计划。历史分配也参与读取过滤。
- 核销、计划登记、采购付款和合同审批检查所有实际涉及的模块操作权限。
- 财务概览 CSV 改由服务端鉴权和生成，前端使用已加载报表期间，避免输入日期未查询时导出不同期间。
- 会话鉴权请求使用 Django 标准 CSRF Cookie / Header；UI 验收使用独立数据库与本地来源信任配置，不改变生产来源信任。

## 测试与 UI 证据

新增 FinanceDataScopeTests 覆盖 self / department / department_tree / all、客户收款正常与拒绝路径、共享供应商付款、公共费用、越权创建 / 重绑定 / 核销 / 作废、退款恢复、计划与合同变更、预收预付分配、拆分及历史分配、重记来源、现金统计与导出一致性和服务端导出权限。无数据库特定 DISTINCT ON，PostgreSQL 由 CI 验证。

Codex 内置浏览器使用隔离账号执行真实 UI 验收：各范围分别显示 1 / 2 / 3 / 4 个客户应收计划；self 可见共享供应商付款与公共费用；共享应付登记 10 元后待结余额从 100 降至 90。截图上传 ux-review-evidence 的 ux-review/r0-d4b2a-finance-scope/。

## BLOCKED / 业务决策

历史销售类型流水若已丢失客户、订单和计划关联，当前结构不能可靠还原其销售归属。不能通过备注或参考号猜测。此类记录对受限范围账号隐藏，仅 all 范围且具备模块权限的人员可查看处理；不改变金额、记账或历史快照。恢复具体销售归属或确认应转为公共费用，需要业务核对，未实施自动迁移。真正的无关联公共费用及共享采购仍正常访问。
