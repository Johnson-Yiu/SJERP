# 报价工作台与重要备注设计

**日期：** 2026-08-18  
**状态：** 已确认，待实施

## 目标

将报价详情从通用关联抽屉升级为报价专用工作台。它应围绕日常报价跟进工作展示 PI、版本谱系、订单转化和重要沟通备注，同时保持报价历史不可被后续版本或主数据变更混淆。

## 范围

本次仅替换报价管理的详情体验；订单及其他业务页面继续使用现有详情组件。既有 PI 预览、Excel 导出、报价迭代及订单编辑能力必须保持可用。

## 页面与交互

点击报价列表任一记录，打开报价专用详情工作台。顶部固定显示客户、报价单号、报价状态、报价总额、当前版本和原始报价号。

顶部动作如下：

- **预览 PI**：打开当前报价版本的 PI 预览。
- **导出 Excel**：下载当前报价版本的 Excel。
- **创建迭代版**：进入既有的迭代编辑流程。
- **转为订单**：创建已从当前报价版本预填的订单草稿。

工作台提供以下分页：

1. **概览**：汇总金额、有效期、基础信息、最新版本及订单摘要和快捷动作。
2. **报价明细**：仅显示当前版本的商品、数量、单价、小计、运费、折扣和备注。
3. **版本谱系**：显示同一原始报价下的原始版和所有 `-1` 至 `-99` 修订版。当前版本高亮；点击版本切换到该版本详情，不修改任何历史数据。
4. **订单**：按当前原始报价链汇总所有版本转出的订单。每条显示订单号、来源报价版本、订单状态、金额及交期；支持打开订单详情，以及预览该订单来源版本的 PI。
5. **重要备注**：显示整个版本链共享的沟通备注，支持新增和标记失效。

报价详情中不得出现“新增 SKU”等通用关联操作。

## 订单转化

“转为订单”从当前报价版本创建订单草稿，带入客户、商品、数量、单价、币种、汇率、运费、折扣及备注。用户可补充交期及订单信息后保存。

订单保存成功后：

- 订单回链到当前报价版本；
- 当前报价版本自动更新为“已接受”；
- 同一报价版本允许创建多张订单，以支持分批下单；
- 原始报价链的订单分页显示全部相关订单，并保留各自来源版本。

若报价没有有效商品、请求无权访问或草稿创建失败，系统显示明确错误，且不创建半成品订单、不改变报价状态。

## 重要备注

重要备注是独立记录，绑定到原始报价链以及创建时的具体报价版本。所有版本详情页都显示该链的全部备注；每条备注必须注明来源报价号/版本、创建人及创建时间。

备注采用富文本输入，支持段落、加粗、列表和链接。前端使用浏览器原生可编辑区域；服务端使用 `bleach` 按白名单净化 HTML 后再保存，前端仅渲染该净化结果。空内容不可提交。备注不写入 PI 或 Excel。

用户可将备注标记为“不再生效”。这不是删除：记录继续显示失效标识，正文以删除线呈现；该操作需二次确认。

备注分页顶部固定提示：

> 备注可能对应不同报价版本，部分内容可能已经过时，且未必适用于最终订单。请结合沟通记录和来源版本判断。

## 数据、权限与测试

- 版本谱系以原始报价为唯一链路，订单和备注按该链聚合。
- 现有报价快照机制继续作为 PI、导出和历史明细的来源。
- 订单转化、订单/报价详情、富文本备注均遵循已有登录与角色权限边界。
- 自动化测试覆盖版本谱系查询、跨版本订单汇总及来源标记、订单预填和状态更新、备注共享及失效、权限和失败响应。
- 验收包含后端完整测试、前端构建，以及人工检查报价详情、PI 预览、订单草稿、版本切换和备注失效显示。
