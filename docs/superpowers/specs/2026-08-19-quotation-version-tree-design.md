# 报价版本树与修订说明设计

**日期：** 2026-08-19  
**状态：** 已确认，直接实施

## 目标

为同一原始报价下的迭代版本保留真实的直接修改来源，并让用户在创建和浏览版本时看见修改说明、树状从属关系与可返回的详情导航。

## 数据模型

`Quote` 保留既有的 `root_quote` 和递增的 `revision_no`，新增：

- `parent_quote`：可空的自关联外键，表示当前修订直接从哪一个版本修改而来；仅修订版设置，且必须属于同一个 `root_quote`。
- `revision_summary`：修订说明。新建原始报价为空；调用修订接口时必填、去首尾空格后至少一个字符。

历史修订版的数据迁移将 `parent_quote` 设为其 `root_quote`，因为历史记录没有保存实际来源。新的修订版始终将调用 `/revise/` 的报价作为 `parent_quote`。编号仍按根报价链分配，因而从 `-1` 修改出的版本可以是 `-3`。

## API 与行为

- `POST /api/quotes/{id}/revise/` 接收 `revision_summary`；缺失或空白返回 400 且不创建版本。
- 工作台响应中的每个版本返回 `parent_quote`、`parent_quote_no`、`revision_summary`，并按照根报价与父子关系输出；订单、备注仍按 `root_quote` 聚合。
- 序列化器将父版本字段设为只读，避免普通创建或更新伪造树关系。

## 界面

- 报价修订编辑器在保存区上方显示“本次修改说明 *”多行输入框，仅在修订模式显示。
- 版本摘要和“版本谱系”分页按树渲染。每个节点展示单号、版本名、日期、状态、金额、修改说明和“预览 PI / 查看详情”。
- 从当前详情切换到另一版本后，标题左上角出现大尺寸“返回上一版本”按钮；返回栈仅在同一详情会话中有效。关闭按钮保持关闭整个报价工作台。
- 详情抽屉的关闭/返回控件使用统一的显眼图标加文字按钮样式，适用于报价和通用实体详情。

## 验收与回归

- API 测试覆盖：修订说明必填、`-3` 能从 `-1` 分支、父版本字段正确、历史迁移默认挂在原始报价。
- 前端构建通过；人工验证版本树、PI 预览、查看详情后返回，以及原有订单/备注聚合不受影响。
