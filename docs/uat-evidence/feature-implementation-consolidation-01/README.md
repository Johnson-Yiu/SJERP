## 范围与方法

复用 [BRANCH-AUDIT-AND-CLEANUP-01](../branch-audit-and-cleanup-01/README.md) 的 276 个远端和 306 个本地引用记录，以及 [BRANCH-CLEANUP-02](../branch-cleanup-02/README.md) 中的补丁身份和恢复记录。现场快照有 227 个远端分支。历史已删除的 51 个远端引用仍保留其审计 SHA；可达的历史实现继续参与功能对照。当前远端 ALEX 分支和本地同名分支均出现后续运维差异，已按共同基线复核。

[功能—实现索引](feature-implementations.tsv)按功能和完整 SHA 归组，别名合并显示。[候选路径清单](candidate-paths.tsv)包含 204 个引用记录、110 个去重后的候选 SHA、1,521 条净差异路径记录，含业务代码、迁移、测试、夹具和相关工具。路径索引用于查找候选，重复编辑的文件、尚未证明的替代实现及测试夹具都可能出现在同一功能下；目录名和提交名只用于分流。已整合的历史提交和单纯证据仍通过原审计引用和各模块证据栏定位。[范围快照](scope.json)列出改动、缺席和计数。工作树未提交内容不作为历史分支实现，也未接入。

对存在竞争实现的场景，对照入口、请求及数据边界、迁移依赖、持久化口径和当前异常断言。相同补丁或同终态作为实现证据之一，再核实现行路径有无逆转。共享模型和 API 的差异按业务语义归入多个模块，单独比文件长度或运行时间无法证明行为。

## 上线决策顺序

| 检查点 | 通过条件 | 若失败时的最小接收范围 |
| --- | --- | --- |
| 从历史 PostgreSQL 库升级，风险高，仅在沿用旧库时适用 | 在实际版本的脱敏副本上从原迁移记录前进。核对两条 0120、0121 回填和 0123 汇合前后的行数、现金分摊、手续费抵扣和应收余额，并验证备份恢复。 | 只补可证明必要的追加迁移或隔离升级步骤及用例。保留原文件、迁移键和依赖链。旧 0120 的无条件全量回填会覆盖已存在的拆分值。 |
| 报价风险确认、失败和重试，风险高 | 用隔离 Chrome 验证风险服务报错、取消不产生导出、重试重新核对、修订确认前保留编辑器以及未保存 SKU 禁止核实。 | 优先把历史 `r1-sku-01-fix-01.spec.js` 的具体断言和合成夹具接到现行 runner。只有确认业务回归时才修改当前风险确认调用点。 |
| 财务窄屏，风险中，按实际终端决定 | 若日常使用 390px 或原生 125% 缩放，验证银行资金、交易流水、账户对账的表头、尾列、详情和操作入口。 | 只修当前失败页的容器与对应浏览器断言。保留现有资金及核销数据模型。旧 flex 方案有局部滚动价值，三个页面的模板已分别演进。 |
| 实际实例数据库与私有媒体联合恢复，风险高 | 在获准的目标拓扑用现行工具跑一次隔离恢复，核对业务记录与附件摘要。 | 缺验收场景时优先复用旧合成夹具。ALEX 的包校验、虚拟机和服务工具留在其运维任务内。 |

已确认的可后置差异包括小数 MOQ 即时提示误报和采购 SKU 快速切换的慢响应断言。Node 探针显示 JavaScript 的 `0.58 × 100` 低于 58，现行与旧 MOQ 分支共享该近似数判断；正式下单使用 Decimal，等值验证通过。若排期修复，只调整草稿提示和等值回归。正式 Shipment XLSX 延用现行导出、数量和权限检验，原生 Excel 实机分页维持延期范围。全局导航文案或大范围组件改版不进入这次整合。

## 定向验证

从上述 SHA 解包后端和模板，使用已安装的项目 Python 依赖，内存 SQLite、独立媒体目录和合成夹具运行两组定向用例。[13 项全部通过](targeted-verification.tsv)，覆盖必填主体快照、重复源行和部分履约、入库冲销和失败无副作用、独立手续费、分摊回填、看板/钻取/CSV 一致、库存审计失败后同键重试、MOQ 等值和停用供应商过滤。测试中的审计异常是故障注入。两组创建新库时均沿当前迁移图执行。

这些结果支持现行业务路径和空库迁移。已有 PostgreSQL/浏览器证据见分模块矩阵。本轮未跑旧库 PostgreSQL 升级、真实 Chrome 或全量测试；未执行 ALEX 配置，未合并、删除或推送任何分支。
