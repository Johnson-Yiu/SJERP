## 本轮交付

1. 财务流水成为收付款、日常费用的主要导航入口；人民币资金和账户资金原有数据、服务、路由与权限保留，但从主导航隐藏。
2. 外币收款保存客户汇款额、银行实际到账额、扣费承担方、扣费依据和私有凭证。公司承担扣费时，只有凭证完整才允许按汇款额分配；客户承担或待查时，未收差额继续留在应收。
3. 原收款详情显示原币实收、汇款额、扣费依据/凭证、核销分配、计划剩余应收、未分配金额，并提供登记结汇入口。
4. 从原收款登记结汇，按已确认原币实收控制额度，支持部分结汇及多笔收款合并。每笔结汇保留原币来源、扣费前人民币兑换额、实际汇率、手续费、净到账、银行日期、参考汇率比较及凭证；结汇不会新增客户收款或重复核销。
5. 新增 append-only 授权抹零记录：金额、原因、确认身份快照、请求键和审计记录单独保存；不新增现金流水，影响应收计划余额。操作重试幂等，审计写入失败时与业务记录一起回滚。
6. 增加订单费用入口，可选样品/打样、模具、验货、运费、报关、仓储、佣金及其他订单费用，并可关联订单。现有期间费用类型继续可用。

## 复用能力与未覆盖项

- 复用 `PaymentPlan`、`AdvanceAllocation`、`record_contract_payment`、`allocate_advance` 处理分期、部分付款、未分配预收预付和后续核销；一笔未分配款可多次分配到同客户/供应商的不同计划。
- 复用 `RmbCashEvent`、`CashSourceAllocation` 实际人民币现金事实，以及既有私有凭证、银行账户校验、财务权限、审计、对账、退款/退回/转账和更正服务。人民币直接收付、独立银行手续费、转账核实、分类和双人复核原页面仍可通过现有路由访问，但本轮没有把所有表单迁入财务流水页面。
- 订单采购成本继续使用既有 `PurchaseCostAllocation`；订单费用沿用订单利润服务的已确认费用归集。
- 垫付与报销关联、避免费用重复归集，以及可退押金原记录/剩余可退金额/退款关联：尚无统一流水关系模型与操作入口。
- 从原交易直接发起商业退款、银行退回和录入更正的源选择入口，以及授权抹零记录的反向更正链：尚未在财务流水详情接通。已有 ISS-108 服务保持原审批、凭证、双人复核及 fail-closed 规则；授权抹零后原流水作废会被拒绝，需后续追加可追溯的抹零更正流程。
- 账户期初、银行对账单导入匹配、期末余额核对、总账、固定资产折旧、报税继续按需求延期。

这些未覆盖入口不改变当前 ISS-105/108 状态；后续处理须沿用现行权限、来源不可覆盖与审批要求，并补真实 PostgreSQL 并发验证。
