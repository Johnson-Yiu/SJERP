# 交接 B：历史财务接续统一服务接口

本包现有 `backend/crm/history_operational_finance.py` 已通过 `crm.services.finance_closeout` 的 `submit / approve / post / cancel / fail` 接续资金事实；页面需要提交真实账户、实际凭证、实际日期、核实后的人民币金额和理由。执行者与复核者分离，结果未知不能标为失败，须有“未发生扣款”证明。此处不复制旧财务记账服务。

请 B 在统一服务复核中确认并书面答复：

- 历史已确认流水仅凭来源原始凭证、真实性及完整关联组核验后接续；来源幂等键稳定绑定到原系统/记录/类型，不因响应丢失生成新业务键。
- 银行期初余额只登记为启用基准，不变成新收款/收入事实；历史已收/已付不能重复生成资金流水或再次冲销应收应付。
- 已核实历史发生事实、未结余额接续草稿和新增经营收支之间边界明确；一个事实不能同时作为历史转移记录和新业务资金事件重复计入。
- 不改变财务已有不可变快照和金额口径；历史源字段未知时保持未知，不以当前账户/主体主档推断。
- `submit` 的幂等冲突/断线结果查询能够依据稳定历史来源返回原指令；禁止用户端通过新 token/请求键重试创建第二笔。
- 期初余额、多币种重估、内部转账、退款、更正、核销及来源冲突是否已有统一服务覆盖；若有缺口列出接口/测试与实施责任，不在本包复制规则。

真实资料和账户基准尚未提供，本包没有真实资金数据、没有调用真实账户、没有实际财务入账。合成测试通过不代表 B 的跨包接口验收或正式财务启用完成。
