# HISTORY-IMPORT-DELIVERY-01 交付与操作说明

## 当前边界

可准备资料和在专用隔离库试导；正式导入须另行申请和授权。没有取得用户真实文件，未对真实列名、缺失值、金额或业务事实做适配和验收。模板从目标系统下载，以其当前版本为准；本目录空模板由源码生成，历史承接为 v2，销售草稿模板没有版本号。`synthetic-*-example` 标明模拟，仅供理解字段。`rehearsal-source.xlsx` 是自动测试的合成工作簿，为走通受控审核路径在隔离测试内填了“真实”，绝不能在真实库或正式业务中使用；其凭证及人物均为虚构。

## 按顺序准备

1. 客户主档：数据导入中的客户 CSV，系统模板字段 `code,name,country,source,website,address,notes`，`code` 客户编号和 `name` 名称必填。保留原有业务编号和前导零；先预览新增与更新，已有编号更新可能覆盖资料。客户示例使用 UTF-8 BOM。
2. 已发生的销售/采购业务：下载历史资料承接 v2 XLSX。分组填写来源关联组编号、原系统、导出日期、资料覆盖和真实性；销售订单填写原系统记录及订单编号、日期、状态、客户历史名称、币种、合同汇率、运费、折扣和真实性；销售明细填写父记录编号、明细编号、历史名称、单位、基础数量及单价、真实性。采购订单及明细类似，另需供应商历史名称。历史编码可空，保留原型号、规格和快照；具体必填字段和允许值以模板与预检为准。历史名称和当前主档不能凭相似性自动视为同一对象。
3. 收付款计划记录原计划编号、订单或采购来源、方向、计划与已核销金额、币种、状态、明细完整性、真实性及凭证；流水另记录原流水号、日期、方向、类型、原币金额、币种、历史折算汇率、来源状态和对应订单/计划。实际人民币到账以银行等凭证另行核实，在受控资金承接中填写，不能由合同汇率推测。履约记录保留事件、父单和行编号、日期、数量、状态、冲销关系及凭证；库存盘点保留仓库归属、仓库、批次、日期、数量、覆盖范围和凭证。缺证据保持待核实，不填猜测值。
4. 在隔离库上传预检，核对来源行和组内阻断、警告及人工核实；修正源资料后重新预检。核对客户/供应商与历史主体，缺正式 SKU 可先按系统规则归档，之后人工核实规格和单位再关联。预检不批准、不执行。
5. 审核通过后按组归档，先核对结果、错误、审计和来源映射；失败先核对该组状态和既有来源，再按系统规则安全重试。仅归档或关联不会生成正式资金、库存或履约事实。未结应收应付、库存基准及剩余履约需要独立的受控申请、证据和审批；历史已发生收发货不应重新记一次。
6. 对实际文件保留原始文件及 SHA-256、批次、预检、审批和核对结果在仓库外。对同一币种分别核对来源商品、运费、折扣、订单及收付，不跨币种相加；核对来源计划与正式余额及实际人民币事实的对应关系。不同范围或尚未受控承接的差额列待核实，不自动补金额、汇率或余额。
7. 新销售草稿另用销售订单导入 XLSX：来源订单编号、客户编号、日期、币种、SKU、交易单位、数量、单价必填；客户、SKU及交易单位须已存在。该入口只创建草稿，不能代替已收款或发货历史业务。USD 未填写汇率的草稿默认值以模板说明为准，不可据此推断历史事实。

[合成报告](synthetic-reconciliation.json)包含归档后、商品关联后和资金承接后三个阶段，`baseline_counts` 是归档前隔离库快照。测试源码 SHA `fa2fc86672588ac6a67b43991b99e93ed0e0dc7f`；后续交付提交只添加文档和合成证据。历史工作簿 SHA-256 `27d397e06afe959d210d8512f2855ce4f435f3ff42e8b9c7210e0936e35e3e11`；客户 CSV SHA-256 `b7f946c8e4907874422ae046116a0dc43f2031ca4cc39e232c89020fa1685361`。

有效组 `HT-G1`：15 条来源记录、1 客户、2 销售单（部分完成和已完成）、1 采购单、3 条商品行；另有 `HT-G-ERROR` 错误组阻断，未生成来源目标记录。空 SKU 归档后 3 行待关联；创建一个 B 后 3 行关联，SKU 总数 1。逐行映射及预检原因见报告。USD 销售商品/订单 240，采购商品/订单 15，运费和折扣各 0；来源收款 40、付款 5。来源计划分别为应收 100/已核销 40、应付 15/已核销 5，均为 USD；这不是已建立的正式余额。报告中正式余额为 0，因为本批未执行剩余业务接续，来源计划仍需核实。独立资金承接把合成源收款对应合成凭证人民币实收 287.43；它不将原币 USD 40 和人民币 287.43 相加，也不自动接续应收。归档及关联后资金、交易、库存流水、预留、收货和发货均为 0；资金承接后资金事实 1，其余仍为 0。

同一工作簿字节重复提交复用原申请；不同文件的重复来源经来源唯一性校验拒绝；错误组审核拒绝；注入组内后续写失败后整个组回滚，再按原组执行成功并重放幂等；资金需不同审核人，重复入账不新增事实。测试未执行正式库存基准、未结余额和剩余履约接续，也未把它们算作通过。名称/规格冲突、更正及其他场景仍须按既有专项测试和实际来源逐项验收。

## 只读核对命令

在目标隔离环境中先确认连接库，使用相同源码、无未提交的后端/模板改动，并提供实际申请 ID、完整源码 SHA、原始工作簿；命令核对工作簿 SHA-256 与申请记录一致，不执行任何业务写入：

```powershell
cd backend
python manage.py reconcile_history_import <申请ID> --source-sha <完整源码SHA> --source-file '<原始工作簿绝对路径>' > '<仓库外的私有报告路径>.json'
```

报告按申请及组输出预检、来源行号与目标、历史商品状态、订单服务计算金额、源计划、分币种来源流水、按来源键对应的人民币资金事实、剩余履约快照。`global_fact_counts` 是**全库**快照，只能在专用隔离库对比前后；不能把全库计数归因于某个组。未执行组的映射为空；未证实资料、来源完整性及未入账金额列待核实。导出可能含客户、交易和凭证引用，应存仓库外并限制访问。命令本身不建立 SKU、不审批、不修账或补汇率。

## 正式导入前

业务、财务、仓库需提供真实原始文件及凭证、范围/截止日、编号和单位换算、客户供应商 SKU 映射、资金及实际人民币到账依据、未结余额和履约、盘点及所有权，并逐项确认冲销、重复和更正链。需隔离试导对账、差异处置、备份恢复演练、审批职责和目标环境权限验收，再另行申请正式导入；不以本合成试导代替。未设定真实启用日和余额，未正式导入或部署。
