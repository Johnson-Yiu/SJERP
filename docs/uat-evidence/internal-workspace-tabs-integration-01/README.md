## 冲突与接线

|冲突|处理|
|---|---|
|`frontend/src/router.js`|保留基线登录、新品提醒入口和认证门禁。共用业务路由表，登录页独立渲染。|
|`frontend/src/api.js`|保留 CSRF 及 403 后核对实际身份的逻辑。确认过期后清理工作区、撤销旧访问状态、替换至登录页。旧请求返回或排队重试时检查会话世代。|
|`frontend/scripts/run-isolated-browser-tests.mjs`|并存原受限账号及开发工作区 Chrome 配置。新增只对本用例生效的隔离双账号种子，保留原 ISS-055 种子。|
|`frontend/browser-tests/import-ux.spec.js`|保留基线 CSV 保存文件和字节断言，采用工作区的切换与回到待执行任务断言。导入页面只接入标签页的通用请求绑定，未接入单独冻结的历史上传候选。|

应用壳层接入退出前的脏稿确认，取消时不发送退出请求。确认并收到服务端成功后卸载全部工作区，清理浏览器历史中的当前工作区身份。失效登录保留站内业务返回路径，移除创建和编辑参数。账号按服务端用户 ID 隔离。新品提醒使用工作区 API，客户及跟进来源分别标识上下文，详情在同一提醒工作区打开。

- 隔离 SQLite 的 Django 认证、身份和新品提醒测试发现 21 项，19 项通过，2 项跳过。
- 工作区管理器 12 项、API 与安全返回 Node 测试 9 项通过，生产构建通过。Vite 保留超过 500 kB 的产物提示。

- 集成专项使用本机真实 Django 会话及两个同名合成账号。失效场景仅删除测试浏览器的会话 cookie。先取得上一账号的真实 HTTP 200，再延迟交付，验证切换账号后该响应被拒收。
