## 结论

本轮确认 1 个真实缺口并完成最小修复：CSV 请求在 DRF 将请求分类为 `export` 动作时，后端函数只显式检查了 `reports.export`，没有在函数内再次要求 `reports.view`。因此在 RBAC 场景下，拥有报表导出权限但没有报表查看权限的账号可以直接调用 CSV API。修复后报表 API 和 CSV API 均要求 `reports.view`，CSV 仍额外要求 `reports.export`；来源模块、维度和数据范围权限仍分别校验。

未发现需要改代码的其他问题：

- `ReportsPage` 将草稿表单和 `applied` 查询状态分离，`ReportBlock` 查询与导出均使用最后一次已提交条件。
- 销售/采购金额按订单汇率折人民币并在 CSV 表头、说明中标识；账面收支与银行实际人民币资金使用不同来源、标签和说明。
- 数量以 `quantities` 按单位分别累计；比例指标当前不在报表指标集合中。
- `safe_csv` 保护客户、筛选标签、分组标签和数量文本中的公式前缀；CSV 实际响应带 UTF-8 BOM。
- 共享模板在服务端重新校验当前账号的模板、来源、维度和数据范围，不使用发布者权限执行查询。
