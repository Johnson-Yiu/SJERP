## Chrome Use 实际结果

Chrome 扩展在首次尝试时受其他会话占用而断开，随后恢复。恢复后新建真实 Chrome 标签页打开 `quotes?detail=2`，完成以下检查：

1. 桌面宽度：打开保存修订版 `ISS020-Q-A-1` 的“预览 PI”，页面可见“已保存报价预览”、历史买方、Version B Recipient、空邮箱 `—`、EUR、历史型号、247.50 和英文金额大写。截图已由 Chrome Use 在本轮对话中输出。
2. 390×844：同一保存修订版在窄屏打开预览，DOM 与页面截图均可见历史收件人、空邮箱占位、历史型号、EUR 247.50、金额大写和条款。PI 保持正式文件的固定打印宽度，窄屏出现文档横向滚动，这是打印布局的现有行为，未改写业务数据。
3. 修订编辑器：打开“创建报价修订版”时，当前 SKU 主档显示 `ISS020-MODEL-CURRENT`，但已载入的报价型号仍是保存的 `ISS020-MODEL-HISTORICAL`，说明编辑器区分当前参考资料和已保存报价事实。
4. 页面按钮“导出 Excel”已定位并点击；浏览器下载事件未在等待窗口内返回，因此不将该点击宣称为浏览器下载通过。实际导出字节由 API 端点成功保存并由 `api-evidence.json` 核验。

## 仍需独立环境补验

- 未使用生产账号、PostgreSQL、反向代理或 Excel 桌面打印机。
- 页面未执行保存新修订版，避免改变合成验收数据；未保存草稿与保存版本的独立入口由前端测试及编辑器状态人工核对。
- Chrome Use 截图作为本轮对话中的视觉证据；若审查流程要求仓库内 PNG 文件，应在具备截图文件落盘能力的浏览器会话中补存，不以工具输出之外的路径冒充文件。
