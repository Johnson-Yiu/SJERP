## 真实 Chrome 操作结果

通过 Chrome 打开采购管理，执行了以下流程：

1. 新建采购单，选择“库存参考验收供应商”和 `INV3-STOCKED-001`。
2. 确认库存参考区域显示基础单位 `pcs`、实际库存 `100`、已预留 `30`、可用库存 `70`、在途采购 `40`。
3. 输入数量 `12` 并保存采购草稿；系统生成采购单号 `PO-2026-00001`，数量保持 `12`。
4. 重新打开草稿并进入编辑，库存参考仍正确显示。
5. 切换至 `INV3-EMPTY-002`，显示 `box` 基础单位及全为 `0` 的库存数据，不误报有库存。
6. 展开 SKU 资料，确认规格、参数、定制说明和历史版本入口；历史版本明确标注不代表库存批次版本。
7. 在 1440px、1024px、700px 宽度下检查采购弹窗，窄屏下内容换行且不出现水平溢出；700px 下使用弹窗自身滚动查看下方内容。

## 权限和边界

开发身份会统一放行页面权限，因此无库存权限的视觉状态未在当前浏览器身份下伪造。后端 `crm.tests.test_inventory_reference.InventoryReferenceTests.test_sku_detail_does_not_turn_hidden_inventory_into_zero` 以关闭 inventory view 的真实 API 权限配置验证：库存字段为 `null`，不是错误的 `0`；采购页面的无权限分支和失败/重试文案由前端组件保留。

库存参考只读，不改变采购数量、库存预留、采购成本、订单履约或付款计划；版本记录只调用现有 SKU 历史接口，不把 SKUVersion 当作库存批次。
