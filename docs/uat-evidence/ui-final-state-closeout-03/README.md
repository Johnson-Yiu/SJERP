基线为 `dd019e98f932668ae851dc0c4c7f602f888d51f9`。分支为 `codex/ui-final-state-closeout-03`，仓库为 Johnson-Yiu/SJERP。四项产品修复在 `6478391e8fcec926f2db1d6e80a6db418658f89f`。嵌套详情恢复的补修在 `26c2a7c07da976e2ff792331d1ed84e1042bbf98`。Chrome 用例使用独立数据库、媒体目录和合成资料。

| 问题 | 复现依据和修复 |
| --- | --- |
| 长客户名挤压主联系人徽章 | E1 扩展 10 的原生 125% 截图显示徽章多行。联系人身份文本允许在剩余宽度内换行，徽章按自身宽度保持一行。测试断言文字行数和抽屉边界，并点开关联企业后返回。 |
| 图片清除后立即重开显示旧图 | E2 记录 DELETE 成功、列表尚未刷新时重开仍显示旧图。保存及图片接口响应先更新列表中的对应行，再关窗并刷新。浏览器挂起列表刷新验证上传及替换后立即重开，并使清除后的列表刷新失败来验证无旧图。批量图片重试只保留未成功的 SKU。 |
| 库存流水无批次标识 | E2 记录同仓两条流水的接口批次不同，详情无展示。基础信息显示已有批次资料。测试以接口中的真实批次核对详情，覆盖同仓同 SKU 两批次、手工调整、采购入库和采购冲销。 |
| 收货取消后焦点丢失 | E2 在合成校验失败后取消能关窗，但焦点未回到入口。收货弹窗记录实际入口。取消、Escape 关闭和入库完成后恢复可用入口，入口不可用时回到采购工作台。测试检查校验失败后取消、Enter 重开和 Escape 返回的实际焦点。 |

[状态核销与剩余状态](states.md) · [CI](https://github.com/Johnson-Yiu/SJERP/actions/runs/42964010798)

本包的 Chrome 用例通过仓库现有隔离运行器逐文件执行，需要开发验收身份和独立种子库。通用浏览器组会注明跳过本包的独立用例。共享运行器、工作流和公共台账归对应工作包维护。

联系人故障补验发现，嵌套详情在失败时仍保留父级身份，原重试按钮因此调用父级。重试现使用失败的目标，成功后可返回同一跟进。加载与错误期间仍沿用父级抽屉的名称，测试在这两个阶段定位同一抽屉，恢复后断言联系人详情。

首次联系人矩阵复跑在 100% 的三种宽度通过，切换至 125% 后沿用同一详情地址未得到新的页面上下文，后续复跑先进入联系人列表再打开指定详情。收货事件参数增加触发按钮后，初次 Vitest 的两项旧参数断言失败，补上按钮身份断言后 51 项通过。

SKU 和收货专项运行于 `a3f389b98dc0007ab476290b7d3fbaee44db8aae`。联系人两项运行于 `26c2a7c07da976e2ff792331d1ed84e1042bbf98`。两个提交之间的唯一产品变更是共享详情的失败目标重试，SKU 和收货产品代码相同。原始运行日志和首次失败保留在本地，入库截图和索引来自上表的通过运行。证据提交继续正常触发 CI。

本轮续验的首次失败、通过结果及剩余组合见 [本轮补验索引](states.md#本轮补验索引)。附件挂起与删除失败、收货入口消失采用受控条件；附件写入、删除重试、文件读回、发货与库存退回登记均使用隔离后端。

附件删除失败补验发现，390×844／125% 的浮动错误提示遮挡表单底部按钮。复现步骤为编辑已有附件的跟进记录，确认删除，对此次 DELETE 注入 400，保留编辑器并观察保存按钮。基线截图取自 `7de892a453f221481c7460eecb82a304f3557edc`。[修复前截图](attachment-delete-overlay-before-390-125.png)

`ResourcePage.vue` 将附件删除错误放进跟进表单底部，和上传失败分别保留。删除失败显示中文提示，旧附件可继续重试，保存及取消保持可达。冻结产品提交为 `2eea14b541077db72246af236ca87a44ce79666e`。该提交只修改跟进附件错误的产品逻辑，收货和库存读回的既有证据适用。
