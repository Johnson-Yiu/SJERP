## 一、完整业务流程

```text
客户线索
  -> 联系人/客户画像
  -> 跟进记录与下一步计划
  -> 产品分类/分类属性
  -> 产品主档
  -> SKU 与参数组合、Sales Model、交易单位、包装模板、供应商来源
  -> 报价（草稿/已发送/已接受/已拒绝/已过期）
  -> 报价版本修订
  -> 销售订单（草稿/已确认/生产中/已发货/已完成/已取消）
  -> 应收计划/回款
  -> 采购与供应商分配
  -> 到货入库、库存流水、库存预留
  -> 装箱/发货/物流
  -> 订单完成、毛利与财务流水
```

## 二、最小分支流程

### 客户与跟进

- 客户状态：线索、联系人、商机、正式客户、公司客户。
- 客户可关联联系人；联系人可用于跟进记录。
- 跟进方式可输入电话、邮件、微信、视频会议、现场拜访等；记录主题、解决方案、客户回复、下一步和下次跟进日期。
- 客户改名、区域、状态、网站、备注后，需要验证订单、报价、跟进仍按客户 ID 关联。

### 分类、产品与 SKU

- 新建根分类 -> 新建子分类 -> 子分类继续新建下级（当前 UI 覆盖到二级层级）。
- 分类可创建属性；属性可控制是否生成中文 SKU、Sales Model、自动大写、是否必填。
- 子分类继承父分类属性；继承属性在子分类中只读。
- 产品可挂根分类或子分类，可维护名称、英文名称、型号前缀、状态、供应商、描述。
- SKU 可由属性组合生成，存在基础单位、交易单位、供应商来源、包装模板和历史版本。
- 已有报价/订单引用的 SKU 修改时必须核对：SKU Code 不变、历史单据快照不变、当前 SKU 列表仍可检索。

### 报价

- 草稿、已发送、已接受、已拒绝、已过期五种状态。
- 报价可包含一个或多个 SKU、交易单位、数量、单价、运费、折扣、条款和备注。
- 编辑报价不是覆盖原单，而是生成修订版本；原始报价保留，修订说明进入版本谱系。
- 已接受报价可转订单；订单应保存成交时的报价版本。
- 国家/地区会参与报价保存校验，需覆盖支持与不支持国家的异常分支。

### 订单、库存与财务

- 报价转订单后可修改预计交期、状态、折扣、条款和明细；需核对应收金额、来源报价和 SKU 快照。
- 订单状态与实际履约记录存在联动；已发货不应只靠手工改状态，需要真实库存/出库/发货流水。
- 订单后续应覆盖采购、部分到货、库存预留、部分发货、尾箱策略、回款、退款/退货、完成和取消。
- 当前本轮未创建采购单、库存流水、发货单和财务流水，因此这些分支仍需下一轮补测。

## 五、重点下游核对

### SKU 修改后订单是否还能找到 SKU

通过 UI 修改 SKU-000003 的中文/英文描述，并修改产品前缀、分类属性名称后：

- SKU 列表仍显示 SKU-000003，报价次数和订单次数未丢失。
- 订单明细仍可打开，仍显示 `SKU-000003`、原成交 Sales Model `XMBL-1830K`、原内部名称和原始描述快照。
- SKU 历史版本页面出现 v1，记录了 `description_cn、description_en` 变更。
- 结论：当前设计通过 SKU Code 和订单快照保护历史单据，未出现“SKU 修改后订单无法找到 SKU”。

### 产品前缀修改后的影响

产品“超薄面板灯”前缀从 `XMBL` 修改为 `XMBP` 后，已有 SKU 仍保留 `XMBL-*`；这符合历史身份不重写的预期。后续新建 SKU 应继续核对新前缀是否生效。

### 客户改名后的影响

- 订单列表显示新客户名称“巴黎酒店照明项目-改版”，订单仍可打开。
- 报价列表仍显示创建时的“巴黎酒店照明项目”，客户筛选项也保留旧名称。
- 这不是关联丢失，但说明报价存在客户名称快照或未同步刷新，建议产品确认是否要统一显示实时客户名。

### 报价修订后的影响

编辑报价会创建 `SJ20260922FRxxx-1` 修订版本，原始报价编号、金额和状态不被覆盖；订单来源报价仍指向成交时的原始/对应版本。

### 订单折扣后的影响

订单折扣从 USD 0 调整为 USD 30 后，订单总额和应收计划从 USD 1,370 调整为 USD 1,340，来源报价仍保持 USD 1,370。该差异符合“订单成交条件可独立于原报价调整”的设计，但需要财务侧确认修订审计是否足够明确。

## 六、异常与阻塞

1. 维也纳客户国家为“奥地利”、柏林客户国家为“德国”时，报价保存返回 `Unsupported country`，表单保留未落单；法国客户报价可以保存。需要补齐国家/地区编码映射或明确支持范围。
2. SKU 编辑页的“中文 SKU 名称”和“Sales Model”字段显示为只读，无法直接修改；当前可修改的是描述，型号变更需要通过属性/生成规则或专门版本流程完成。
3. 订单编辑页手工选择“已发货”后，保存提示“到货、发货状态由实际出入库记录自动更新”，状态保持“生产中”。该约束符合履约闭环，但必须通过采购、入库、出库、发货数据才能覆盖已发货/已完成分支。
4. 选择包装模板后若 SKU 包装行缺少整件数量，保存会失败；补齐单个重量和整件数量后保存成功。该校验有效，但错误提示可进一步明确到具体包装行。
5. 当前系统没有独立售后/赔偿业务模型；退款交易、退货入库和售后成本只能通过已有财务/库存模型表达。
