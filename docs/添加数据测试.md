# 添加数据测试

## 1. 测试目标

本次测试按照真实业务顺序逐条新增数据，不采用批量导入或批量接口生成业务单据。每条订单均按照“客户/跟进 → 报价 → 订单 → 采购 → 入库 → 付款 → 收款 → 出库”的顺序执行，并在每个关键节点检查前后数据是否一致。

## 2. 主业务流程

客户管理 → 联系人 → 跟进记录 → 报价 → PI/预计装箱单 → 报价转订单 → 订单确认 → 按订单行指定供应商 → 采购单 → 验货入库 → 供应商付款 → 客户收款 → 销售出库 → 订单履约闭环。

产品资料缺失时，需要先建立：产品分类 → 产品属性 → 产品 → SKU → 供应商货源 → 包装模板。产品资料已存在时，可以直接进入报价。

## 3. 主要分支流程

- 报价：草稿、已发送、已接受、已拒绝、已过期、报价迭代。
- 库存：有现货时直接预留并出库；库存不足时指定供应商、创建采购单、到货验收、入库后再出库。
- 到货：全量到货、部分到货、不合格品、拒收、补货。
- 收付款：定金/尾款、部分收款、超额收付款、未分配预收预付、退款/折让。
- 订单：草稿、已确认、生产中、已发货、已完成、已取消。
- 售后：退货、退款、赔款、库存回冲、合同变更。

## 6. 已发现的业务问题

### P1：订单无法自然推进到“已完成”

全额收款、全部出库后，订单自动变为“已发货”；尝试改成“已完成”时，又因已有采购、库存和收付款记录而被禁止保存。

建议：增加“完成订单”动作，或在“已收清、已全量出库、采购无未结”的条件满足后自动推进到“已完成”。

### P1：财务流水新增记账金额校验异常

财务流水表单显示金额已填写为 `415.00`，保存仍提示“收付款金额必须是大于零的有效数字”；通过“应收计划 → 登记收款”则可以正常登记。

建议：检查 `v-money-input` 与 Vue `v-model` 的绑定，统一金额输入组件，并增加前端保存前 payload 检查。

### P1：报价定金比例未正确持久化

报价编辑时填写定金比例 30%，PI 仍显示 100% 预付款、0% 尾款。

建议：检查报价表单字段绑定、保存 payload 和 PI 读取逻辑，增加保存后回读测试。

### P1：库存流水列表可能截断数据

本轮 30 条订单预计产生 64 条采购入库/销售出库流水，但库存流水列表默认只显示 50 条；按具体订单搜索时可以查到对应流水。`ResourcePage` 当前直接读取单页数据，而后端分页大小为 50。

建议：统一使用分页聚合函数或增加清晰的分页控件和总记录数。

### P2：国家/地区名称不统一

客户允许填写“德国”“英国”，但报价编号生成器只支持部分本地化名称和英文名称，导致报价保存时报 `Unsupported country`。

建议：国家字段使用标准字典，内部统一存储 ISO 国家代码。

### P2：PI 金额大写出现 `undefined`

PI 中出现类似：`SAY TOTAL undefined FOUR HUNDRED FIFTEEN ONLY`。

建议：修复币种名称映射，并增加 USD、EUR、GBP 等币种的金额大写测试。

### P2：供应商供货特点格式要求未在 UI 中体现

后端要求每行填写“名称：内容”，但 UI 看起来允许任意文本，格式错误时只能在保存后返回错误。

建议：增加示例、前端预校验和格式化提示。

### P2：采购单不会自动回填订单行供应商

采购单已关联订单并选择供应商，但订单履约页仍显示“未分配”，需要再次逐 SKU 指定供应商。

建议：创建关联采购单后自动回填订单行供应商，同时保留人工更换能力。

## 7. 测试结论

主流程已经可以跑通，30 条订单的报价、订单、采购、入库、付款、收款、出库和财务数据保持一致。

当前优先修复顺序建议为：

1. 订单“已完成”状态流转。
2. 财务金额录入校验。
3. 报价定金比例持久化。
4. PI 金额大写。
5. 国家/地区标准化。
6. 库存流水分页和数据展示。

## 9. 本轮发现的预期外问题和风险

### 9.1 已确认的业务问题

1. **全损入库无法落库，且界面无反馈。**

   当剩余待入库数量为 9、合格入库数量填写为 0、并勾选损坏说明时，“确认入库”按钮看起来可用，但点击没有任何结果。系统不能记录“0 件合格入库、9 件全损”，也没有生成损耗、报废、索赔或库存调整流水。

   建议：入库模型拆分为“合格入库数量、损坏/报废数量、异常原因、责任方、证据附件、供应商索赔状态”；允许合格数量为 0 但损坏数量大于 0，并要求填写原因后生成独立库存事件。

2. **订单状态保存依赖交期天数，缺少清晰的字段校验。**

   在把订单改为“已确认”等状态时，如果交期天数为空，页面返回“日期格式错误，请从 YYYY-MM-DD 中选择”，实际问题是交期相关字段为空或未完成计算。填入交期天数后才可保存。错误信息与真实原因不一致，会误导业务人员。

   建议：保存前直接校验交期字段，明确提示“请输入交期天数或交货日期”；后端也应返回字段级错误，不要把空值转换成日期格式错误。

### 9.2 需要进一步核对的业务风险

3. **订单采购数量口径可能存在重复计算。**

   在采购数量为 5 且已全部收货后，订单工作台曾显示“已采购 10”，同时显示“已到 5/在途 5”。采购单本身记录为采购 5、已收 5、剩余 0。该现象可能是“订单需求预留量”和“采购单数量”同时计入，也可能是已采购数量的重复累计，当前证据不足以最终定性。

   建议：用订单行、采购单行、库存预留和入库流水四个口径建立明确公式，并增加一条端到端数量一致性校验：订单需求 = 已下采购单 + 未采购需求；采购单数量 = 已入库 + 在途 + 损耗/取消数量。

4. **采购单“已完成”可能只代表到货完成，不代表付款完成。**

   `PO-20260921-002351` 已全部入库，但供应商应付款仍为 CNY 17.50，采购列表仍显示“已完成”。如果“已完成”只代表到货完成，应在界面上改为“到货完成”或拆分“到货状态/付款状态/采购结案状态”，避免误认为采购财务也已结清。

5. **售后赔款对原收款计划的影响规则未明确。**

   当前可以新增客户退款/折让流水，但不会自动冲减原订单金额和应收计划。这个行为未必是程序错误，但必须在业务规则中明确：退款是独立售后费用，还是应冲减销售收入、订单实收和客户应收余额；不同选择应对应不同财务处理和报表口径。

尚未完成有效验证的状态或能力：

- 订单真正进入“已完成”的状态；
- 财务流水真正进入“已作废”的状态；
- 合格入库数量为 0、损坏数量等于全部待入库数量时的损耗落库；
- 采购短缺后的补采、替代供应商、客户部分交付或订单拆分交付。

总体结论：系统可以承接客户跟进中、报价未完成、订单未付款、部分收款、已发货未收款、采购部分到货和售后赔款等大部分中间状态；但对全损入库、损耗库存、订单完成态、采购数量口径和售后退款会计归属仍存在明显缺口，需要修复或补充业务规则后，才能认为系统能够覆盖完整的现实异常流程。

## 11. 修复建议优先级

### P0：必须优先修复

- 支持“合格入库 0 + 损坏/报废数量 > 0”的损耗入库，并生成可追溯库存流水。
- 修正入库确认失败时无任何提示的问题，后端返回明确的校验错误或业务失败原因。
- 核对订单已采购、已到货、在途数量的计算口径，避免重复计数。

### P1：上线前应修复

- 将交期为空导致的日期错误改为字段级校验提示。
- 拆分采购到货状态、供应商付款状态和采购结案状态。
- 明确退款/折让是否冲减订单应收，并同步收款计划、收入和售后费用报表。
- 补充订单“已发货 → 已完成”的明确触发条件和可追踪状态流转。

### P2：完善性工作

- 增加补采、替代供应商、部分交付、拆单发货、客户拒收和运输损坏分支。
- 增加损耗、索赔、保险理赔和责任认定的附件与审计记录。
- 对财务流水作废、退款冲销和已核销收款计划恢复建立可回滚的操作日志。
