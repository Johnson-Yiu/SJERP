## 5. 发现的问题

### P1：美元客户收款在“新增记账”入口无法保存

复现：财务流水 → 新增记账 → 类型“客户收款” → 选择美元销售订单 → 输入 USD 2,375、汇率 7.2、订单和付款信息 → 保存。页面输入框显示 `2375.00`，但仍提示“收付款金额必须是大于零的有效数字”，流水不生成。

对比：同一笔美元收款通过“应收计划 → 登记收款”可以正常保存，并成功核销。因此当前可用绕行路径是从应收/应付计划结算；“新增记账”入口的金额控件或表单状态同步需要修复。

### P1：部分国家无法保存报价

客户国家为 Sweden 时，报价保存返回 `Unsupported country`，报价编辑器不关闭且不生成报价；此前 Germany / Austria 也出现同类现象。法国客户可以正常报价。本问题会阻断特定国家的报价业务。

### P2：客户“下次跟进”留空时仍触发日期格式错误

客户基本信息中不填写下次跟进日期，保存提示“日期格式错误。请从这些格式中选择：YYYY-MM-DD。”手工填写日期后才可保存。若该字段设计为可选，应允许留空；若必填，应在字段上明确标识。

### P2：产品选择根分类后的归类结果不稳定

创建“户外防水投光灯”时选择父分类“商业照明”后，产品列表显示为“未分类”；其他选择子分类“酒店面板灯”的产品正常显示父子路径。需要明确父分类是否允许直接挂产品，或在 UI 中阻止/引导选择可挂载的子分类。

### P2：报价收件人邮箱输入值未稳定保留

在报价编辑器中输入买方邮箱后回查，输入框未保留该值；本次业务未依赖邮箱保存。建议检查该字段的 v-model / 保存 payload 和回填逻辑。

### P2：SKU 级 Supplier Source 是采购候选的实际前置条件，但提示不足

产品已维护两个供应商并不代表每个 SKU 自动有候选供应商。第二个 SKU 首次在订单行分配供应商时显示“候选供应商（0）”，补齐该 SKU 的 Supplier Source 后才出现候选。业务规则本身合理，但订单分配处应更清楚提示“请先维护 SKU 级供货档案”。

### P3：开发环境操作日志明确未开启

订单工作台“操作日志”显示“开发环境暂不记录”。这符合当前开发环境约定，但上线前需补齐日志记录和验收。

## 6. 结论

当前系统已通过一条完整的真实用户主链路：客户、产品、SKU、供应商、报价修订、订单、采购、入库、库存、出库、应收、应付和财务概览能够形成可回查的业务闭环，数量和金额在跨模块之间保持一致。

但尚不能判定为“无阻塞上线”：美元“新增记账”入口和部分国家报价保存属于 P1 阻断问题；客户可选日期和父分类归类属于 P2 表单/业务规则问题。建议先修复 P1，再进行第二轮回归，重点复测 Sweden/Germany 等国家、财务流水直接记账、订单回款与采购付款的多币种路径。
