## 2. 按提示词梳理的业务流程与覆盖结果

### 2.1 CRM 主链路

客户建立 → 联系人建立 → 客户阶段/国家信息 → 跟进记录 → 客户详情回查。

结果：已测试客户和联系人逐条创建、客户搜索、联系人回查、跟进记录保存。客户日期字段和联系人邮箱字段发现表单问题，见缺陷章节。

### 2.2 产品、SKU 与供应商链路

产品分类 → 产品建立 → 产品参数/证书 → SKU 向导 → Sales Model → 包装/交易单位 → SKU 级 SupplierSKU → 订单行供应商候选。

结果：已通过 UI 创建 50 个产品和 302 个 SKU；测试了 3 个产品的 SKU 归属、多个 Sales Model、包装和交易单位。已验证：产品级供应商并不会自动成为 SKU 候选，必须维护 SKU 级 SupplierSKU。

### 2.3 报价链路

客户 → 需求 → 新建报价 → 选择 SKU → 数量 → 单价 → 币种 → 折扣/费用 → 保存 → 状态推进 → 编辑/修订 → 接受 → 订单关联。

结果：已建立 201 份报价，覆盖 draft、sent、accepted、rejected、expired；已验证 2 个报价版本，原版本不被修订版覆盖；已验证报价到订单的关联。报价当前涉及 11 个客户和 EUR/GBP/USD 三种币种。

未完成：报价批量数据主要集中在可保存报价的国家；部分国家因国家字典校验阻塞，未能自然形成完整报价网络。

### 2.4 销售订单链路

报价/直接需求 → 订单客户 → 订单状态 → 订单 SKU 明细 → 数量/销售价/成本 → 币种/汇率 → 应收计划 → 供应商/采购 → 入库 → 预留 → 出库 → 发货 → 收款 → 成本/利润 → 完成。

结果：已逐条创建 100 笔订单，30 个客户有实际订单，覆盖 USD/EUR/GBP/CNY；订单状态真实落库为 confirmed、production、shipped。已有 2 笔报价关联订单。

注意：100 笔订单中 99 笔为单 SKU、1 笔为 2 SKU，数据多样性不足；新增订单主要停留在确认/生产中，未把每笔订单都推进到采购、入库、出库、收款和完成。

### 2.5 采购、库存、发货和财务链路

订单行供应商候选 → SupplierSKU → 采购单 → 采购成本分配 → 到货/验货 → 入库 → 库存流水 → 订单预留 → 出库 → 发货 → 应收/收款 → 应付/付款。

结果：此前已通过 UI 完成一条 2 SKU 订单的采购、成本、验货入库、库存预留、两次出库、发货、应收分次收款和供应商付款闭环；最终订单自动变为已发货，库存 purchase_in/sale_out 和财务流水可回查，金额在订单、库存、应收和财务间一致。

当前规模数据中，采购/入库/出库/发货仍只有少量真实闭环记录，未按 100 笔订单全部扩展。

### 2.6 异常、取消、回退和售后

已实际触发：缺少 SupplierSKU 候选、无效客户日期、国家不支持、直接记账金额校验失败、订单“已完成”前置条件校验、表单取消和报价取消路径。

未形成完整业务记录：库存不足占用、供应商少发/多发、损坏、部分退款、部分补发、客户取消、采购后取消、售后赔偿、售后额外物流成本、多次发货、一个采购单服务多个销售订单等。

原因：当前前端没有独立售后模块；订单“已完成”不能直接从已发货编辑表单选择，系统将已发货状态禁用并提示由出库自动更新，未找到可继续关闭订单的完整 UI 入口。

### 已验证的副作用检查

## 5. 跨模块一致性

已核对通过的闭环：

CRM → 报价 → 订单 → SupplierSKU → 采购 → 成本分配 → 入库 → 库存 → 出库 → 发货 → 应收收款 → 应付付款 → 财务流水。

该闭环以一笔 2 SKU、已收清、已发货订单为基准核对，订单金额、库存入出库数量、应收核销、应付核销和财务流水一致。

规模数据的限制：99 笔新增订单仍主要只有订单与自动应收计划，采购、库存、物流和收付款没有逐笔自然联动；因此不能把“100 笔订单已建立”误解为“100 笔订单都已完成全链路验收”。

## 6. 缺陷与风险

### P1：部分国家无法保存报价

- 复现：客户国家选择 Sweden/Finland 等 → 新建报价 → 选择 SKU → 保存。
- 预期：报价正常保存并生成编号。
- 实际：页面返回 `Unsupported country`，报价不生成。
- 涉及模块：客户、报价、报价编号。
- 稳定性：稳定复现于不在当前支持国家字典的国家。
- 风险：阻断特定国家的报价业务。

### P1：美元客户在“新增记账”入口无法保存

- 复现：财务流水 → 新增记账 → 客户收款 → 美元订单 → 输入金额和汇率 → 保存。
- 实际：提示“收付款金额必须是大于零的有效数字”，流水不生成。
- 对比：从应收计划 → 登记收款可以正常核销。
- 风险：财务人员从直接记账入口无法完成美元收款。

### P1：订单完成态及取消态缺少可用闭环

- 复现：新建订单时直接选择“已完成”，保存不落库；编辑已发货订单时，“已发货”被禁用且无法选择“已完成”。
- 预期：已发货且收款完成的订单可以通过明确的完成动作关闭；取消订单应有可追踪的取消和库存/应收回退。
- 实际：只验证到已发货，未找到完整关闭/取消 UI 流程。
- 风险：100 笔订单不能真实覆盖完成、取消、回退和结案。

### P2：客户“下次跟进”留空仍报日期格式错误

- 实际：空值保存提示 `日期格式错误。请从这些格式中选择：YYYY-MM-DD。`。
- 风险：可选字段行为与 UI 认知不一致。

### P2：客户/报价收件人邮箱输入值未稳定保留

- 实际：输入后回查未稳定保留。
- 风险：报价发送和联系人信息准确性受影响。

### P2：父分类直接挂产品后显示“未分类”

- 实际：选择父分类“商业照明”后产品列表可能显示“未分类”；选择子分类时正常。
- 风险：产品归类和筛选结果不稳定。

### P2：SupplierSKU 前置条件提示不足

- 实际：产品级供应商存在，但订单行候选供应商仍为 0；补齐 SKU 级 SupplierSKU 后才出现候选。
- 风险：采购人员容易误判为供应商数据丢失。

### P3：开发环境操作日志未开启

- 实际：订单工作台显示开发环境暂不记录操作日志。
- 风险：上线前缺乏完整审计追踪。

## 7. 最终结论

数量门槛已达到：50 客户、30 个成交客户、201 报价、100 订单、50 产品、302 SKU；所有这些业务数据均通过 Browser 前端逐条创建，未使用 API、SQL 或导入绕过 UI。

系统目前可以承接：客户与联系人维护、报价及报价状态、报价修订、基础订单建立、多币种订单、供应商 SKU 候选、采购入库、库存出入库、发货、应收登记、供应商付款和基础财务回查。已有一条真实的 2 SKU 订单完成了跨 CRM/报价/订单/采购/库存/发货/财务闭环，历史 SKU 快照也验证通过。

系统目前不能据此判定为可完全依赖的生产系统，主要原因是：

1. 订单规模数据大部分停留在确认/生产中，完成、取消、回退、退款和异常履约覆盖不足。
2. 售后没有独立前端业务入口，补发、赔偿、退款和售后成本无法按提示词要求形成完整闭环。
3. 部分国家报价和美元直接记账存在 P1 阻断。
4. 新增 100 笔订单没有全部自然产生采购、入库、出库、物流和收付款链路，跨模块一致性只能对已完成的小规模闭环确认，不能外推到全部订单。

建议下一轮先修复 P1，补齐订单完成/取消及售后入口，然后用 10～20 笔订单专门构造部分付款、部分发货、少发、多发、损坏、退款和多采购单场景，再执行全链路回归。
