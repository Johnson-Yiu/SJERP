# 采购明细成本分配

来源：用户提供的《团队管理问题描述》讨论。采购单记录采购事实，明细成本可拆给多个销售订单，余量归库存；公共费用按占比分摊，订单预估毛利使用分配成本。

## 操作

采购管理 → 采购单“操作” → “分配采购成本 / 公共费用”，也可点击明细的“分配成本”。展开明细后调整归属、订单、数量，增加运费、关税等附加费用，点击“保存并计算分摊”查看服务端结果。

每条明细支持销售订单、库存、样品、损耗；未填写的剩余数量自动补到库存。已填库存数量可减少后拆给订单。数量不能超出该采购明细。订单不要求包含相同 SKU，因此可将电线等材料成本归给成品订单。

金额使用采购单币种；附加费用支持按商品金额或数量分摊，库存、样品、损耗同样分担。零金额采购需用按数量分摊。采用十进制定点运算和最大余数法处理分币尾差；每条商品明细金额四舍五入至两位，分配后金额与该口径守恒。跨不同计量单位使用按数量分摊前需确认数量具有可比性。

## 历史与利润口径

版本 0 的历史采购继续整单归原关联订单，无关联订单则归库存。首次保存后启用明细归属，原关联订单不再决定成本，避免重复统计。销售订单详情展示分配商品成本、附加费用及预估毛利。采购成本按各采购单汇率换算人民币；草稿和取消采购不计入利润。库存部分不会计入任一订单的成本，后续可重新分配。

这里记录的是采购成本归属，不是已销售商品成本结转。库存归属不代表已验收入库，不改变库存数量、入库单价或现有库存预留规则。订单履约的采购数量按归属取数；同一明细的到货进度按归属数量比例展示，不等同于分订单验货记录。

公共费用记录不自动生成支出流水或供应商应付计划。实际付款仍使用现有财务流程；已在采购中分摊的费用不要再作为订单费用登记，否则会重复计入预估毛利。采购单供应商应付金额仍为商品合同金额。

## 完整性与接口

`GET/POST /api/purchase-orders/{id}/cost-allocation/`。POST 包含 `version`、`allocations` 和 `expenses`，全量替换分配。服务端锁定采购单、校验版本和明细归属，拒绝无效数值、超分、取消订单及错误目标；失败整体回滚。保存前后分配写入现有操作记录。

已有成本分配的采购单禁止改写商品、供应商、币种、汇率和原始整单订单字段，归属通过分配入口调整。开发超级管理员约定及权限开关保持原状。
