请检查当前项目中“报价单自动生成 Excel 并导出”的完整实现链路，并对其进行一次架构级重构。

## 一、重构目标

当前报价单 Excel 的数据与样式主要通过代码生成。这个方案虽然可以正常工作，但存在明显的长期维护问题：

- 修改背景颜色、字体、边框、列宽、Logo 位置等纯视觉内容时，也必须修改代码；
- Excel 的业务逻辑和表现层耦合；
- 后续如果增加多个报价单模板，代码容易快速膨胀；
- 普通的 Excel 格式调整无法直接通过修改模板完成；
- 前端可能承担了过多报价单导出数据的组装和格式化职责。

本次重构的目标是：

> 保留“系统自动生成 Excel”的能力，但将 Excel 的静态布局和视觉样式迁移到 `.xlsx` 模板文件中，让代码只负责业务数据、动态内容和模板渲染。

目标架构：

```text
Quotation Database
        ↓
Quotation Snapshot
        ↓
Export DTO
        ↓
Template Selection
        ↓
Excel Renderer
        ↓
Generated .xlsx
```

请先完整分析当前实现，再在不破坏现有报价单业务功能的前提下完成重构。

# 三、核心设计原则

本次重构必须明确区分以下四层。

## 1. Quotation Business Data

负责报价单本身的业务数据。

例如：

```json
{
  "quotation_no": "QT-2026-00125",
  "customer": {},
  "currency": "USD",
  "items": [],
  "subtotal": 0,
  "discount": 0,
  "total": 0,
  "payment_terms": "",
  "delivery_terms": ""
}
```

这一层不能包含 Excel 视觉样式信息。

禁止在业务对象中加入类似：

```text
backgroundColor
fontSize
columnWidth
borderStyle
rowHeight
```

之类的 Excel 表现层字段。

---

## 2. Export DTO

建立专门用于报价单导出的 DTO / View Model。

例如：

```text
QuotationExportDTO
```

它负责把数据库中的报价单转换成 Excel Renderer 可以直接使用的数据。

原则：

> Excel Renderer 不应该直接到处查询 Customer、Product、SKU 等业务表。

应该先由 Export Service 统一组装 Export DTO。

这样 Excel 渲染器只关心：

```text
“我要把什么数据放入模板”
```

而不是：

```text
“这些数据应该去哪里查询”
```

---

## 3. Excel Template

建立真实 `.xlsx` 模板文件，例如：

```text
templates/
    quotation/
        quotation_standard_en.xlsx
```

具体目录请根据项目现有结构选择合理位置。

模板应承担以下内容：

- Logo
- 公司名称
- QUOTATION 标题
- 字体
- 字号
- 背景色
- 边框
- 单元格对齐
- 行高
- 列宽
- 合并单元格
- 静态文字
- 打印方向
- 页边距
- 页眉页脚
- 打印区域
- 其他纯视觉内容

原则：

> 普通用户以后打开 Excel 模板修改颜色、字体、Logo、列宽等视觉内容后，不需要修改程序代码。

---

## 4. Excel Renderer

代码只负责模板无法静态完成的内容，例如：

- 加载模板；
- 填充固定字段；
- 根据产品数量生成动态产品行；
- 复制模板产品行；
- 插入产品图片；
- 写入数量；
- 写入单价；
- 写入金额；
- 写入折扣；
- 写入汇率；
- 写入总金额；
- 根据明细数量移动下面的区域；
- 处理动态公式；
- 必要时调整分页；
- 最终输出 `.xlsx`。

Renderer 不应重新定义整个 Excel 视觉系统。

# 五、动态产品行

这是本次重构的重点之一。

不要在代码中重新生成整张报价单。

模板中应预留一行或一个区域作为：

```text
ITEM_TEMPLATE_ROW
```

Renderer 根据报价单 items 数量动态复制这一行。

例如：

```text
模板：

第 8 行 = 产品模板行

如果报价单有 5 个产品：

复制第 8 行样式 →
生成第 8~12 行
```

必须正确复制：

- 单元格样式；
- 边框；
- 填充色；
- 字体；
- 数字格式；
- 对齐；
- 行高；
- 合并关系（如果存在）；
- 公式逻辑（如果适用）。

然后将：

```text
Item No.
Image
Model
Description
Quantity
Unit
Unit Price
Amount
```

分别写入对应单元格。

动态产品行生成后，下方：

```text
Subtotal
Total
Payment Terms
Remarks
```

等区域应自动移动到正确位置。

# 六、模板字段定位方式

不要大量依赖：

```text
A1
B7
F23
H35
```

这种散落在代码中的魔法坐标。

优先采用以下方案之一：

### 方案 A：Named Range

如果当前使用的 Excel 库支持，优先使用 Excel Named Range。

例如：

```text
QUOTATION_NO
CUSTOMER_NAME
QUOTATION_DATE
CURRENCY
SUBTOTAL
TOTAL
ITEM_TEMPLATE_ROW
```

Renderer 根据 Named Range 查找目标位置。

### 方案 B：集中式 Template Mapping

如果当前库对 Named Range 支持不好，则建立统一映射：

```javascript
const quotationTemplateMap = {
  quotationNo: "F3",
  customerName: "B4",
  quotationDate: "F4",
  itemTemplateRow: 8,
  subtotal: "H20",
  total: "H21"
}
```

禁止在业务代码的不同位置散落大量 Cell Address。

# 七、报价单快照

请重点检查当前报价单是否已经具备完整的 Snapshot 机制。

原则：

> 已经确认或保存的历史报价单，重新导出时不应该因为产品主数据后续发生变化而改变历史报价内容。

例如：

报价时：

```text
Model: ABC-001
Description: COB LED Strip 24V
Price: USD 2.35
```

三个月后产品库改成：

```text
Model: ABC-001A
Description: High Density COB Strip
Default Price: USD 2.70
```

重新导出旧报价单时必须仍然显示：

```text
ABC-001
COB LED Strip 24V
USD 2.35
```

因此请检查 quotation item 是否已经保存必要快照字段，例如：

```text
sku_code_snapshot
product_name_snapshot
model_snapshot
description_snapshot
unit_snapshot
unit_price
discount
currency
image_snapshot / image reference
```

如果目前已经有类似机制：

> 保留现有机制，不要重复造表。

如果没有：

请设计尽可能小的数据库调整方案实现报价单快照。

不要为了“架构完美”大规模重构整个 Product / SKU 系统。

# 八、前端职责调整

请检查当前是否存在：

```text
Frontend
    ↓
收集报价单数据
    ↓
重新组装 / 格式化 Excel 数据
    ↓
POST 数据给后端
    ↓
后端生成 Excel
```

如果是，请尽量调整为：

```text
Frontend
    ↓
POST /quotations/{id}/export
    ↓
Backend
    ↓
根据 quotation_id 查询报价单
    ↓
构建 QuotationExportDTO
    ↓
加载 Excel Template
    ↓
生成 Excel
```

即：

> 前端只负责发起导出请求，不负责决定 Excel 数据内容。

这样保证：

```text
数据库中的报价单
=
Excel 导出的报价单
```

避免出现：

```text
数据库状态 A
前端传入状态 B
Excel 导出状态 C
```

但如果当前系统存在：

```text
“未保存报价单也允许预览 / 导出”
```

这种业务能力，则不要直接删除。

请针对当前实际业务做兼容设计，例如：

```text
已保存报价单：
quotation_id → 后端读取数据库

未保存草稿：
draft payload → 临时 Export DTO
```

根据现有系统实际功能决定。
